## 2. アーキテクチャ

Android 公式の「アプリ アーキテクチャ ガイド」に沿って、**UI 層**と**データ層**の 2 層に分ける（ドメイン層は作らない）。

```
┌───────────── UI 層 ──────────────┐
│ Screen（Composable）              │  画面を描く。操作を ViewModel に渡す
│      ▲ UiState     │ イベント     │
│      │             ▼              │
│ ViewModel                         │  画面の状態（StateFlow）を持つ。入力チェック等の画面のルール
└──────┬────────────────────────────┘
       │ suspend 関数 / Flow
┌──────▼───── データ層 ─────────────┐
│ Repository（interface＋実装）     │  データの出し入れ。日時の記録
│      │                            │
│ DAO ─ Room（SQLite）              │  メモ
│ DataStore（Preferences）          │  設定
└───────────────────────────────────┘
```

- **データの流れは一方向**: データ層 → ViewModel → 画面（状態）、画面 → ViewModel（イベント）
- 一覧は Room の `Flow` を購読するので、保存・削除すると一覧が自動で更新される
- 画面のルール（空なら保存できない、変更がなければ日時を変えない など）は ViewModel に置く（[メモ編集 詳細設計](../メモ編集/詳細設計.md)）
- 日時は `java.time.Clock` から取る。テストで時刻を固定できるようにするため（9 章）
- Activity は `MainActivity` の 1 つだけで、画面は Composable で切り替える（[画面一覧](../要件/画面一覧.md) の実装方針）

## 4. メモの保存（Room）

### 4.1 テーブル `memos`

| 列 | 型（SQLite） | Kotlin | 制約 | 説明 |
|---|---|---|---|---|
| id | INTEGER | Long | 主キー、自動採番 | 1 から始まる。0 は「新規（未保存）」を表すのに使う（`NEW_MEMO_ID`） |
| body | TEXT | String | NOT NULL | 本文（最大 10,000 文字。上限は画面側で守る。[メモ編集](../メモ編集/詳細設計.md)） |
| created_at | INTEGER | Long | NOT NULL | 作成日時（エポックミリ秒） |
| updated_at | INTEGER | Long | NOT NULL | 更新日時（エポックミリ秒）。一覧の並び順に使う |

- インデックス: `index_memos_updated_at`（updated_at）。一覧の並び替えを速くするため
- DB ファイル名: `sinmemo.db`（`SinMemoDatabase.NAME`）、バージョン: 1
- スキーマの JSON を `app/schemas/` に出力してコミットする（決定事項 3。将来テーブルを変えるときは version を上げ、この JSON をもとにマイグレーションを書く）
- 自動バックアップ: DB は既定でバックアップ対象になる。`backup_rules.xml`・`data_extraction_rules.xml` に除外の指定はないため、変更しない（[共通 基本設計](基本設計.md) 決定事項 3）。→ 2026-11-17 の開発者の決定で**バックアップしない**に変えた（13.5）

### 4.2 DAO `MemoDao`

| メソッド | SQL（要旨） | 戻り値 | 使う場所 |
|---|---|---|---|
| `observeSummaries` | `SELECT id, substr(body, 1, 200) AS head, updated_at FROM memos ORDER BY updated_at DESC, id DESC` | `Flow<List<MemoSummary>>` | 一覧 |
| `getById(id)` | `SELECT * FROM memos WHERE id = :id` | `Memo?` | 編集画面を開くとき |
| `insert(memo)` | `INSERT` | 採番された id | 新規保存 |
| `updateBody(id, body, updatedAt)` | `UPDATE memos SET body = :body, updated_at = :updatedAt WHERE id = :id` | 変わった行数 | 既存の保存 |
| `deleteById(id)` | `DELETE FROM memos WHERE id = :id` | 消えた行数 | 削除 |

- **一覧では本文全体を読まない**。先頭 200 文字（`head`）だけを読み、メモ 1,000 件でもメモリと読み込み時間を抑える（非機能要件）。200 は `MemoSummary.HEAD_LENGTH` と SQL の両方に書いてあるので、変えるときは両方を合わせる
- `substr` は文字数で数える（日本語も 1 文字 = 1）
- 一覧に出す「最初の空でない行」と「…」での省略は `head` から UI 側で作る（[メモ一覧 詳細設計](../メモ一覧/詳細設計.md)）。先頭 200 文字がすべて空白・改行のメモは、空の行として表示する（まれなので割り切る）。ゼロ幅の文字だけのメモも空に見える。どちらも #59 決定 5 で割り切りのままとした（[メモ一覧 基本設計](../メモ一覧/基本設計.md) 3.1）
- 更新日時が同じメモは id の大きい順（新しく作った順）に並べ、並びが揺れないようにする
- SQL の値はすべて引数で渡す（Room がバインドする）。本文に SQL を混ぜても文字として保存される（[セキュリティ](../セキュリティ/テスト結果.md) の A-6）

### 4.3 リポジトリ `MemoRepository`

| メソッド | 動き |
|---|---|
| `observeSummaries()` | 一覧。保存・削除のたびに新しい一覧が流れてくる |
| `getMemo(id)` | 1 件取得。なければ null |
| `create(body)` | 新規保存。作成日時・更新日時に現在時刻を入れ、採番された id を返す。→ 7.4 で id と更新日時（`SavedMemo`）を返すように変える（13.1） |
| `update(id, body)` | 本文を書き換え、更新日時を現在時刻にする（作成日時は変えない）。→ 7.4 で `SavedMemo?` を返す。0 行（メモがない）なら null（13.1） |
| `delete(id)` | 削除（0 行でも例外にしない） |

- 実装 `RoomMemoRepository` は `MemoDao` と `Clock` を受け取る。現在時刻は `clock.millis()`
- ViewModel のテストでは、この interface の偽物（`FakeMemoRepository`、テスト側に置く）を使う

## 5. 画面遷移（Navigation Compose）

型安全なルート（Kotlin Serialization を使う方式）で定義する（`ui/navigation/Routes.kt`）。

| ルート | 引数 | 画面 | 備考 |
|---|---|---|---|
| `MemoListRoute` | なし | S-01 | 開始画面 |
| `MemoEditRoute` | `memoId: Long`（既定 0 = 新規） | S-02 | `null` を使わず 0 で新規を表す（引数の扱いを単純にするため）。`MemoEditViewModel` は `SavedStateHandle` から名前 `memoId` で読むので、名前を変えるときは合わせる |
| `SettingsRoute` | なし | S-03 | |

- ViewModel は各画面の行き先ごとに `hiltViewModel()` で作る
- **二度押し対策**: 画面を開く・戻る操作は、その行き先（`NavBackStackEntry`）のライフサイクルが RESUMED のときだけ `navigate`／`popBackStack` する（NavHost の中の `ifResumed`）。画面の切り替え中に同じ画面が 2 枚開いたり、戻りすぎたりしないようにする。一覧の 3 つの操作と設定の ← に使う
  - 編集画面から一覧へ戻る（`onClose`）だけは、RESUMED ではなく「この画面がまだ一番上か」で判断する。保存の完了がアプリを裏に回している間になることもあるため（[メモ編集 詳細設計](../メモ編集/詳細設計.md)）
- 編集画面から一覧へ「保存したメモの id」を渡す仕組み（一覧の `SavedStateHandle` のキー `savedMemoId`）は [メモ一覧 詳細設計](../メモ一覧/詳細設計.md) の 7 章
- 起動時に下書きがあれば `MemoEditRoute` を自動で開く処理（T-02 の当初案）→ 作らない。下書きは編集画面の状態として戻す（[下書き 詳細設計](../下書き/詳細設計.md)）

## 6. 設定の保存（DataStore）

Preferences DataStore に保存する（[機能一覧](../要件/機能一覧.md) F-17 の想定どおり）。読み書きの処理と、壊れていたときの扱いは [設定 詳細設計](../設定/詳細設計.md)。

| キー | 型 | 値 | 初期値 |
|---|---|---|---|
| `theme_mode` | String | `SYSTEM`／`LIGHT`／`DARK` | `LIGHT` |
| `font_size` | String | `SMALL`／`MEDIUM`／`LARGE` | `MEDIUM` |

- 値は enum の名前で保存する。知らない値が入っていたら初期値として扱う
- ファイル: `settings.preferences_pb`（アプリの `files/datastore/` の下。→ 2026-11-17 からバックアップしない。13.5）
- DataStore は同じファイルに 2 つ作ると例外になるので、アプリで 1 つだけ作る（7 章の `DataStoreModule`）

## 8. テーマ（配色・文字サイズ）

値は [共通 基本設計](基本設計.md) の 3 章（配色）・4 章（文字サイズ）。

### 8.1 配色（`ui/theme/Color.kt`、`Theme.kt`）

モックアップの配色を Material 3 の `ColorScheme` に当てはめる。`LightColors`・`DarkColors` の 2 つ。

| 用途 | `ColorScheme` の項目 |
|---|---|
| 背景 | `background`、`surface` |
| アプリバー | `surfaceContainer`（`TopAppBar` の色として明示する） |
| 文字 | `onBackground`、`onSurface` |
| 薄い文字（日時） | `onSurfaceVariant` |
| 区切り線 | `outlineVariant` |
| アクセント（FAB 等） | `primary` |
| アクセント上の文字 | `onPrimary` |
| メニュー・ダイアログ | `surfaceContainerHigh` |
| 危険（削除） | `error` |

- 上の表にない項目は Material 3 の既定（`lightColorScheme`／`darkColorScheme` の初期値）のまま
- `SinMemoTheme(darkTheme)` は `darkTheme` で `LightColors`／`DarkColors` を選ぶだけ。ダイナミックカラーの分岐は持たない（決定事項 4）。省略時はライト（プレビュー用）
- 3.2〜4.2 ではライト固定で渡し、6.2 で設定とつないだ。ダークの色も最初に定義し、プレビューで確かめた
- `darkTheme` を決めるのは `MainActivity`（テーマ設定と端末のダークモードから。[設定 詳細設計](../設定/詳細設計.md)）
- `SinMemoApp` は画面全体をテーマの背景色の `Surface` で塗る。画面の切り替え（フェード）の途中に後ろのウィンドウの白が透けないようにするため（[設定 詳細設計](../設定/詳細設計.md)）

### 8.2 文字サイズ（`ui/theme/FontSize.kt`）

| 名前 | 中身 |
|---|---|
| `FontSize`（enum） | `SMALL`／`MEDIUM`／`LARGE`。それぞれ `title`（一覧の 1 行目）・`date`（一覧の日時）・`body`（編集の本文）の 3 つの sp を持つ |
| `FontSize.DEFAULT` | `MEDIUM` |
| `FontSize.from(setting)` | 設定の値（`FontSizeSetting`）から変換する |
| `LocalFontSize` | 今の文字サイズ。`SinMemoApp` が設定から決めて渡し、一覧・編集の画面が読む。変わるのは設定を変えたときだけなので `staticCompositionLocalOf` |

- 一覧・編集の画面は「状態だけで描く部分」（`MemoListContent` など）に `FontSize` を引数で渡す。プレビュー・UI テストで好きな大きさを渡せるようにするため
- 3.2〜4.2 では「中」に固定して渡し、6.2 で設定とつないだ

## 9. 時刻（`Clock`）

- 現在時刻はすべて Hilt が渡す `java.time.Clock` から取る（リポジトリの作成・更新日時、一覧の「今年かどうか」）。テストでは固定の `Clock` を渡す
- 本番の `Clock` は `DeviceZoneClock`（`ClockModule.kt`）。**タイムゾーンを使うたびに端末の今の設定（`ZoneId.systemDefault()`）を読み直す**
  - → `Clock.systemDefaultZone()` から変えた（4.2）。`systemDefaultZone()` は作った時点のタイムゾーンに固定され、アプリの起動中に端末のタイムゾーンが変わる（旅行先で自動設定が働くなど）と、再起動するまで古いタイムゾーンで日時を表示するため。4.2 のエミュレータ確認で、起動直後にタイムゾーンが変わり 5 時間ずれて表示されたことで見つかった
- 一覧を表示したままタイムゾーンが変わったときの制限は [メモ一覧 基本設計](../メモ一覧/基本設計.md) の 3.2。→ 7.4 で端末の知らせを受けて作り直すことにした（13.4）

## 11. テストの仕組み

- DAO・リポジトリ・UI のテストは **Robolectric** で PC 上（`./gradlew testDebugUnitTest`）で動かす。端末がなくても実行できる（決定事項 2）
- DB はメモリ上（`Room.inMemoryDatabaseBuilder`）に作り、テストごとに作り直す

## 13. 7.4 で変えるところ（Issue #59）

[共通 基本設計](基本設計.md) 6 章の作り方。画面ごとの作り方は各機能の詳細設計にある。

### 13.1 リポジトリの戻り値（#59 決定 2・その他）

保存したメモが一覧のどこに来たかを一覧が正しく待てるように（[メモ一覧 詳細設計](../メモ一覧/詳細設計.md) 7.4）、保存で書いた更新日時を返す。

| 変えるもの | 今 | 7.4 |
|---|---|---|
| 新しい型 `data/memo/SavedMemo.kt` | - | `data class SavedMemo(val id: Long, val updatedAt: Long)`。保存したメモの id と、そのとき DB に書いた更新日時（エポックミリ秒） |
| `MemoRepository.create(body)` | `Long`（id） | `SavedMemo` |
| `MemoRepository.update(id, body)` | `Unit` | `SavedMemo?`。`MemoDao.updateBody` の戻り値（変わった行数）が 0 なら null、1 なら `SavedMemo(id, now)` |
| `MemoRepository.delete(id)` | `Unit` | `Unit` のまま（0 行でも何もしない） |
| `RoomMemoRepository` | - | `val now = clock.millis()` を 1 回だけ取り、DB に書く値と戻り値の両方に使う |
| `FakeMemoRepository`（テスト） | - | 同じ戻り値にする。さらに失敗を起こす口を足す（`failNextWith: Throwable?`。次の `create`・`update`・`delete` で 1 回だけ投げる）と、`update` で 0 行を起こす口（`removeBeforeUpdate`） |

- `update` が null のときの画面の動きは [メモ編集 詳細設計](../メモ編集/詳細設計.md) 9.3（設計役の案: 新しいメモとして保存する）
- DAO（`MemoDao`）は変えない（`updateBody`・`deleteById` はもう行数を返している）

### 13.2 DB の失敗の伝わり方（#59 決定 1）

- データ層（DAO・リポジトリ）は**例外を握りつぶさない**。Room が投げる例外（`android.database.sqlite.SQLiteException` とその仲間: 記憶装置がいっぱいの `SQLiteFullException`、`SQLiteDiskIOException` など。DB を閉じた後の `IllegalStateException`）はそのまま呼び出し元へ
- 受け止めるのは ViewModel（[メモ編集 詳細設計](../メモ編集/詳細設計.md) 9.1）。`CancellationException` だけは投げ直し、それ以外の `Exception` を受けて「失敗」として画面に出す
- ログ（`Log.w`）には例外の種類だけを出し、**本文は出さない**（メモの中身をログに残さない）
  - 素の JUnit の単体テスト（Robolectric を使わない ViewModel のテスト）でも `Log.w` で落ちないよう、`app/build.gradle.kts` の `testOptions.unitTests` に `isReturnDefaultValues = true` を入れる（7.4 の実装で足した）
- 一覧の読み込み（`observeSummaries` の Flow）で例外が出たとき: `MemoListViewModel` で `catch` し、直前の一覧のまま（設計役の案。[メモ一覧 詳細設計](../メモ一覧/詳細設計.md) 4.1）

### 13.3 DB の破損（#59 決定 6。割り切り）

| 場合 | 起きること | 対応 |
|---|---|---|
| DB のファイルが壊れている（SQLite が「壊れている」と判断） | Room（`FrameworkSQLiteOpenHelper`）の既定の `DatabaseErrorHandler` が**壊れたファイルを消し**、空の DB を作り直す。メモは消える | 何もしない（割り切り。[共通 基本設計](基本設計.md) 6.3）。`openHelperFactory`・`DatabaseErrorHandler` は差し替えない |
| DB の型の印（`room_master_table` の `identity_hash`）がアプリと違う | Room が `IllegalStateException`（Room cannot verify the data integrity）で落ちる | 起きるのは DB を外から入れたときだけ（`scripts/seed_memos.ps1`）。スクリプトの値とアプリの値が合うことを `SeedScriptConsistencyTest` で確かめる（[共通 テスト設計](テスト設計.md) 2.4） |
| DB の版（`user_version`）がアプリより新しい（新しい版のバックアップを古い版に戻した 等） | Room が落ちる（下げる移行がない） | 今は版 1 だけなので起きない。版を上げるときに考える（`fallbackToDestructiveMigrationOnDowngrade` を使うかどうか） |

- `fallbackToDestructiveMigration` は使わない（今のまま。版を上げるときは移行を書く。決定事項 3）
- `scripts/seed_memos.ps1` は 7.4 で次を直す: `$Package` を `com.example.sinmemo.debug` にする（[共通 基本設計](基本設計.md) 6.1）。`$IdentityHash`・`$DbVersion`・`$DbName` は今の値のまま（テストで合っていることを確かめる）

### 13.4 時刻の変更の知らせ（#59 決定 11）

一覧を開いたまま端末のタイムゾーン・日付・時刻が変わったら、一覧の日時をすぐ作り直す（[メモ一覧 基本設計](../メモ一覧/基本設計.md) 3.2）。端末の知らせ（ブロードキャスト）を Flow にする部品を作る。

| 置き場所 | 名前 | 中身 |
|---|---|---|
| `data/time/TimeChangeSource.kt` | `interface TimeChangeSource` | `val changes: Flow<Unit>`。端末のタイムゾーン・日付・時刻が変わるたびに 1 つ流れる |
| 同じファイル | `class SystemTimeChangeSource @Inject constructor(@ApplicationContext context: Context)` | `callbackFlow` で `BroadcastReceiver` を登録し、`awaitClose` で外す。受ける知らせは `Intent.ACTION_TIMEZONE_CHANGED`（タイムゾーン）、`Intent.ACTION_TIME_CHANGED`（時刻を手で変えた。中身は `android.intent.action.TIME_SET`）、`Intent.ACTION_DATE_CHANGED`（日付が変わった。0 時を過ぎて年が変わったときにも「今年」を作り直すため） |
| `di/ClockModule.kt` | `TimeChangeModule`（`@Binds @Singleton`） | `TimeChangeSource` ← `SystemTimeChangeSource` |

- 登録は `ContextCompat.registerReceiver(context, receiver, filter, ContextCompat.RECEIVER_NOT_EXPORTED)`。システムからの知らせは `NOT_EXPORTED` でも届く。ほかのアプリからの偽の知らせは受けない
- `ACTION_TIMEZONE_CHANGED` を受けたら、流す前に `TimeZone.setDefault(null)` を呼ぶ（設計役の案）。Java が覚えている「今のタイムゾーン」を捨てさせ、`DeviceZoneClock` の `ZoneId.systemDefault()` が新しいタイムゾーンを返すようにする。Android 自身もアプリのプロセスに同じことをするが、この受け手との順番は決まっていないため
- 登録している間だけ電池をわずかに使う。登録は一覧の購読と同じ期間（一覧を見ている間と、離れて 5 秒まで）だけ（[メモ一覧 詳細設計](../メモ一覧/詳細設計.md) 4.2）
- テストでは偽物 `FakeTimeChangeSource`（`MutableSharedFlow<Unit>`）を渡す

### 13.5 バックアップの設定ファイル（#59 その他。開発者の決定（2026-11-17））

[共通 基本設計](基本設計.md) 6.4 の作り方（**バックアップしない**）。

| ファイル | 中身 |
|---|---|
| `AndroidManifest.xml` | `android:allowBackup="false"`（Android 11 以前のバックアップと、Android 12 以降のクラウドへのバックアップを止める）。`dataExtractionRules`・`fullBackupContent` の指定は残す |
| `res/xml/data_extraction_rules.xml`（Android 12 以降） | `<cloud-backup>` と `<device-transfer>` の両方に、`<exclude domain="root|file|database|sharedpref|external" path="." />` の 5 行。`include` は書かない |
| `res/xml/backup_rules.xml`（Android 11 以前） | `<full-backup-content>` に同じ 5 つの `exclude`。`include`・`requireFlags` は書かない |

- Android 12 以降は、`allowBackup="false"` でも端末から端末への移行（`device-transfer`）は行われる。そのため `data_extraction_rules.xml` で全部の場所を外す
- `backup_rules.xml` は `allowBackup="false"` で読まれないが、念のため全部を外す
- 確かめるのは `BackupRulesTest`（C-U-28〜30・35）と、端末での C-D-05（移らないこと）
- → 最初の案（DB と `datastore/` だけを含め、クラウドは暗号化できるときだけ。7.4 の確認で機種変更の `deviceToDeviceTransfer` も足した）は、開発者の決定（2026-11-17）でやめた
