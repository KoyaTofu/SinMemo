## 1. 範囲と ID

基盤（DB・リポジトリ・起動と画面遷移・データが残ること）を確かめる。各画面の中身は各機能のテスト設計、テーマ・文字サイズの反映（`SinMemoAppTest`）は [設定 テスト設計](../設定/テスト設計.md)。

| 接頭字 | 種類 |
|---|---|
| `C-U-xx` | 自動テスト（PC、Robolectric） |
| `C-E-xx` | エミュレータ |
| `C-D-xx` | 実機 |

## 2. 自動テスト（PC、Robolectric）

- 実行: `./gradlew testDebugUnitTest`（Windows は `.\gradlew.bat`）。端末は要らない
- DB はメモリ上（`Room.inMemoryDatabaseBuilder`）に作り、テストごとに作り直す
- リポジトリのテストは時刻を固定した `Clock`（テストの中の `TestClock`、UTC）を使う

### 2.3 自動テストで確かめていないこと

| 項目 | 理由・代わり |
|---|---|
| 二度押し対策（NavHost の `ifResumed`） | PC 上では画面の切り替え中の状態を作りにくいため、専用のテストはない。保存中の二度押しは [メモ編集 テスト設計](../メモ編集/テスト設計.md) で確かめる |
| `DeviceZoneClock` がタイムゾーンの変更に追従すること | 端末のタイムゾーンを変える必要があるため。4.2 のエミュレータ確認で見つけて直した（[共通 テスト結果](テスト結果.md) の 2 章） |
| 本物の DB ファイル・DataStore のファイルがアプリの再起動後に残ること | 実機で確かめる（C-D-01） |

## 4. 実機

実機での確認は [総合テスト](../総合テスト/テスト設計.md) でまとめて行う。ここには基盤に関わるものを挙げ、総合テストの ID を書く。

| ID | 確かめること | 合格の目安 | 総合テストの ID |
|---|---|---|---|
| C-D-01 | 再起動後のデータ保持（メモ 1,000 件・作ったメモ・設定のダーク・大） | 端末を再起動しても残る | N-7 |
| C-D-02 | 起動から一覧の表示まで（リリース版） | 2 秒以内 | N-1・N-2 |
| C-D-03 | 最近使ったアプリから消して開く | メモは残り、書きかけは残らない | S-6・S-9 |
| C-D-04 | デバッグ版とリリース版を並べて入れる（#59 決定 3） | 別のアプリとして並び、データが混ざらない。デバッグ版を消してもリリース版のメモは残る | 5.6（手順はこの書類の 4.1） |
| C-D-05 | バックアップ・機種変更でメモと設定が移らない（#59 その他。開発者の決定（2026-11-17）） | バックアップを頼んでも預けられず、デバッグ版を消して入れ直すとメモ 0 件・設定は初期値 | 5.6（手順はこの書類の 4.2） |

### 4.1 C-D-04 デバッグ版とリリース版を並べて入れる（#59 決定 3）

開発者の端末（OPPO CPH2099、Android 11）で、開発者が手で操作する（この端末は adb のタップを受け付けないため）。

準備: PC で 7.4 のデバッグ版を入れる（`.\gradlew.bat installDebug`）。リリース版は 8.2 で入れたもの（7.4 のリリース版を入れるのは [リリース テスト設計](../リリース/テスト設計.md) の RL-D-07）。

| No | ユーザーの操作 | アプリの動き |
|---|---|---|
| 1 | ホーム画面でアプリ一覧を開く | 「SinMemo」と「SinMemo (debug)」の 2 つが並ぶ。アイコンは同じ |
| 2 | 「SinMemo (debug)」を開く | 一覧が出る。リリース版のメモは出ない（初めて入れたときは 0 件） |
| 3 | 「＋」を押し、「デバッグ版のメモ」と入力して「✓」を押す | 一覧の先頭に「デバッグ版のメモ」が出る |
| 4 | 「⋮」を押し、「設定」を押す | 「バージョン」が「1.0.0-debug」（7.4 の途中では「1.0.1-debug」。公開は 1.0.0 を始点にするため 1.0.0 / versionCode 1 に戻した（開発者の決定 2026-11-17）） |
| 5 | ホーム画面に戻り、「SinMemo」を開く | 自分のメモが出る。「デバッグ版のメモ」は出ない |
| 6 | 「⋮」を押し、「設定」を押す | 「バージョン」が「1.0.0」（RL-D-07 のあとも「1.0.0」。→ 当初は RL-D-07 のあとは「1.0.1」としていたが、公開は 1.0.0 を始点にするため 1.0.0 / versionCode 1 に戻した（開発者の決定 2026-11-17）） |
| 7 | PC で `adb uninstall com.example.sinmemo.debug` を実行する | アプリ一覧から「SinMemo (debug)」が消える |
| 8 | 「SinMemo」を開く | 自分のメモがそのまま残っている |
| 9 | PC で `.\gradlew.bat installDebug` を実行する | 「SinMemo (debug)」が戻る。中のメモは 0 件 |
| 例外 1 | 1 で「SinMemo」が 2 つ並んでいたら（7.4 より前のデバッグ版が残っている）、開いて「⋮」の「設定」の「バージョン」を見る | 古いデバッグ版は「1.0.0」で、リリース版と見分けが付かない。8.2 でリリース版に入れ替えたので、ふつうは起きない。起きたら作業を止め、Claude に知らせる |

※用語：デバッグ版：開発中に PC から入れる版。テスト用のデータを入れられる。リリース版：本物の鍵で署名した、ふだん使う版
※用語：adb：PC から USB で端末を操作するコマンド。ここではアプリを消す・入れるのに使う（タップの代わりには使わない）

### 4.2 C-D-05 バックアップ・機種変更でメモと設定が移らない（#59 その他。開発者の決定（2026-11-17））

アプリはバックアップしない（[共通 基本設計](基本設計.md) 6.4）。預けられず、消して入れ直すと戻らないことを、デバッグ版で確かめる（リリース版の自分のメモは消さない）。機種変更（端末から端末への移行）は、端末が 2 台要るので確かめない。設定ファイルの中身は自動テスト（C-U-28〜30・35）で確かめる。

端末での操作（メモと設定を作る）

| No | ユーザーの操作 | アプリの動き |
|---|---|---|
| 1 | 「SinMemo (debug)」を開き、「＋」で「バックアップの確認」と入力して「✓」を押す | 一覧に「バックアップの確認」が出る |
| 2 | 「⋮」の「設定」で「テーマ」を「ダーク」にして「OK」を押す | アプリがダークになる |

開発者が PC で行う作業

| No | 開発者の作業（PC） | 結果 |
|---|---|---|
| 3 | `adb shell bmgr backupnow com.example.sinmemo.debug` を実行する | `Package com.example.sinmemo.debug with result: Backup is not allowed` と出る（預けられない） |
| 4 | `adb uninstall com.example.sinmemo.debug` を実行する | 端末から「SinMemo (debug)」が消える |
| 5 | `.\gradlew.bat installDebug` を実行する | 「SinMemo (debug)」が戻る |
| 例外 1 | 3 で `Success` と出たら、4 に進まず作業を止め、結果に書く | バックアップが止まっていない（設定の誤り） |

端末での操作（確かめる）

| No | ユーザーの操作 | アプリの動き |
|---|---|---|
| 6 | 「SinMemo (debug)」を開く | 一覧は空（「バックアップの確認」は戻らない）。ライト（初期値）で表示される |

※用語：bmgr：端末のバックアップを PC から操作するコマンド。`backupnow` はすぐ預けようとする
