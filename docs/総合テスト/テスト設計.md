## 5. 実機

### 5.1 準備（開発者の作業。最初に 1 回）

1. スマホ: 設定 → デバイス情報 → 「ビルド番号」を 7 回押す → 開発者向けオプションが出る
2. 開発者向けオプション → 「USB デバッグ」をオン
3. USB で PC につなぐ → スマホに出る「USB デバッグを許可しますか」で、この PC を許可
4. PC で確かめる（PowerShell。リポジトリのフォルダで）
   ```
   & "$env:LOCALAPPDATA\Android\Sdk\platform-tools\adb.exe" devices
   ```
   `xxxxxxxx	device` と出れば OK（`unauthorized` ならスマホの許可を確認）
5. デバッグ版を入れる: Android Studio で上の端末一覧から自分のスマホを選んで ▶（Run）。またはコマンドで
   ```
   $env:JAVA_HOME = 'C:\Program Files\Android\Android Studio\jbr'
   .\gradlew.bat installDebug
   ```

- 以下のコマンドは PowerShell で、リポジトリのフォルダで実行する。`adb` は 4 の長いパスのこと。毎回書くのが面倒なら `Set-Alias adb "$env:LOCALAPPDATA\Android\Sdk\platform-tools\adb.exe"` を先に実行する
- スクリプトの実行が「このシステムではスクリプトの実行が無効」で止まる場合は、`powershell -ExecutionPolicy Bypass -File .\scripts\seed_memos.ps1 seed` のように実行する

### 5.2 7.1 非機能

#### 5.2.0 スクリプト `scripts/seed_memos.ps1` の使い方

端末の SinMemo（デバッグ版）の DB を、テスト用のメモ 1,000 件に置き換える／元に戻す（決定事項 2・3。アプリのコードは変えず、adb で入れる。[スケジュール](../記録/スケジュール.md) 決定事項 8）。

| コマンド | すること |
|---|---|
| `.\scripts\seed_memos.ps1 backup` | 端末の DB を PC に保存するだけ |
| `.\scripts\seed_memos.ps1 seed` | まず backup し、そのあと DB をテスト用 1,000 件だけの DB に置き換える |
| `.\scripts\seed_memos.ps1 restore` | backup で保存した DB を端末に戻す。省略すると、テスト用でない最新の保存（名前が `-seed` で終わらないもの） |

| オプション | 意味 |
|---|---|
| `-From <フォルダ>` | `restore` で戻す保存を指定する（例: `-From "C:\Users\...\SinMemo-backup\20261115-231132"`） |
| `-Serial <端末>` | 複数の端末をつないでいるときに指定する（例: `-Serial emulator-5554`） |
| `-Count <件数>` | 入れる件数（既定 1000） |
| `-BackupRoot <フォルダ>` | 保存先（既定 `%USERPROFILE%\SinMemo-backup`。リポジトリの外。ユーザーのメモが入るため） |

- デバッグ版でしか動かない（`adb shell run-as` を使うため。リリース版は「package not debuggable」で拒まれる）
- DB は PC の `sqlite3.exe`（Android SDK の platform-tools にある）で作る。乱数の種を固定しているので、何度入れても同じ中身
- テスト用の DB には印（SQLite のヘッダの application_id）を付けている。`seed` を 2 回続けても、2 回目の保存はテスト用の印が付いて `-seed` の名前になり、`restore` で選ばれない
- Room の DB の版（identityHash）を書き込んで作るので、DB の作りを変えたらスクリプトも直す
- テスト用のメモの中身（決定事項 4・5）: 日本語の 1 行メモが中心。改行入りの数百文字が約 1 割、上限近く（9,000〜10,000 文字）が 5 件、先頭が空行のものが 2 件。更新日時は過去 1 年に散らしてある（今年は `11/15 14:10`、去年は `2025/11/16 08:47` の形で出る）。上限近くの 5 件は「長いメモ ○」という 1 行目で、更新日時を最新にして一覧の先頭に並べる（「長いメモ 8」〜「長いメモ 778」。「長いメモ 151」は 9,618 文字、334・513 も 9,500 文字以上）

#### 5.2.1 手順の順番

順番が大事（1,000 件はデバッグ版でしか入れられない。リリース版はその上から入れるとデータが残る。決定事項 6）。

| 手順 | 入っている版 | メモ |
|---|---|---|
| ① 1,000 件を入れる | デバッグ版 | ユーザーのメモ → 1,000 件 |
| ② デバッグ版で触る | デバッグ版 | 1,000 件 |
| ③ リリース版に入れ替えて、起動時間と 1,000 件を測る | リリース版（デバッグ用の鍵） | 1,000 件のまま |
| ④ 再起動後のデータ保持 | リリース版 | 1,000 件のまま |
| ⑤ 元に戻す | デバッグ版 | ユーザーのメモに戻る |

#### ① 1,000 件を入れる（デバッグ版）

```
.\scripts\seed_memos.ps1 seed
```
- 最初に端末の DB を `%USERPROFILE%\SinMemo-backup\<日時>\` に保存し、そのあと DB を **テスト用の 1,000 件だけ** に置き換える（今あるメモは画面から消える。決定事項 3）
- 出力の例（予行。[テスト結果](テスト結果.md) 1 章）
  ```
  保存した: C:\Users\...\SinMemo-backup\20261115-231132（sinmemo.db, sinmemo.db-shm, sinmemo.db-wal）
  作った DB: 件数|最長の文字数|最古|最新 = 1000|9618|1763252537779|1794751833725
  端末の DB をテスト用 1000 件に置き換えた。元に戻すとき: .\scripts\seed_memos.ps1 restore（テスト用でない最新の保存を戻す）
  ```

#### ② デバッグ版で触る（参考）

アプリを開き、次をざっと確かめる。デバッグ版は最適化がなく遅いので、合否は ③ のリリース版で決める。

- 一覧が出る。先頭に「長いメモ 8」〜「長いメモ 778」
- 指で速くスクロールして、最後（`2025/11/…` の日付）まで行ける。落ちない

#### ③ リリース版に入れ替えて測る

本物の署名鍵はリリース（[リリース 基本設計](../リリース/基本設計.md)）で作るので、ここでは **Android の開発用の鍵（デバッグ用の鍵）で署名したリリース版** を使う（デバッグ版と同じ鍵なので上から入れられ、データが残る。決定事項 6）。

```
$env:JAVA_HOME = 'C:\Program Files\Android\Android Studio\jbr'
.\gradlew.bat assembleRelease
$bt = "$env:LOCALAPPDATA\Android\Sdk\build-tools\37.0.0"
& "$bt\zipalign.exe" -f 4 app\build\outputs\apk\release\app-release-unsigned.apk tmp\release-aligned.apk
& "$bt\apksigner.bat" sign --ks "$env:USERPROFILE\.android\debug.keystore" --ks-pass pass:android --out tmp\app-release-debugkey.apk tmp\release-aligned.apk
adb install -r tmp\app-release-debugkey.apk
```
- `tmp\` は `.gitignore` 済み。先に `mkdir tmp` が要る場合がある
- `android` は Android SDK が自動で作るデバッグ用の鍵の決まったパスワード（秘密ではない）。リリースで作る本物の鍵とは別
- 入れたら、`adb shell dumpsys package com.example.sinmemo | Select-String pkgFlags` で `DEBUGGABLE` が **ない** ことを確かめる

**起動時間**（3 回）
1. 最近使ったアプリから SinMemo を消す（またはこのコマンド）
   ```
   adb shell am force-stop com.example.sinmemo
   adb logcat -c
   ```
2. ホーム画面のアイコンから起動し、一覧が出るまでの時間を見る（体感でよい。気になるならスマホの画面録画で確かめる）
3. 記録用に次を実行する（`Displayed` は最初の画面＝スプラッシュが出るまでの時間。一覧はその後、設定を読み終わって最低 0.5 秒たってから出る。[設定 基本設計](../設定/基本設計.md) のスプラッシュ）
   ```
   adb logcat -d | Select-String 'Displayed com.example.sinmemo'
   ```

**1,000 件のスクロール**
1. 一覧を指で上下に速くスクロールする（10 秒ほど）。引っかかり・白い空白・落ちることがないか
2. 記録用（スクロールする前に `reset`、した後に表示）
   ```
   adb shell dumpsys gfxinfo com.example.sinmemo reset
   （スクロールする）
   adb shell dumpsys gfxinfo com.example.sinmemo | Select-String 'Total frames|Janky|50th|90th|99th'
   ```
3. 「長いメモ 8」を開く → すぐ開くか、スクロールできるか。✓ を押さずに ← で戻る（変更していなければ確認は出ない）
4. 新しいメモを 1 件作って保存 → 一覧の先頭に出るか

#### ④ 再起動後のデータ保持
1. 設定でテーマ「ダーク」・文字サイズ「大」にする
2. スマホを再起動する
3. SinMemo を開き、1,000 件（先頭に ③ で作ったメモ）とダーク・大が残っているか

#### ⑤ 元に戻す
```
.\gradlew.bat installDebug
.\scripts\seed_memos.ps1 restore
```
- 特定の保存を戻すときは `-From "C:\Users\...\SinMemo-backup\20261115-231132"`
- 戻したら、自分のメモが一覧に出ることを確かめる。設定（テーマ・文字サイズ）は DB と別なので ④ の値のまま。好みに戻す
- `seed` の前に一度も SinMemo を開いていなかった場合（保存に DB がない）は `restore` できない。アプリの「データを消去」で空に戻すか、デバッグ版で `adb shell "run-as com.example.sinmemo sh -c 'rm -rf databases files/datastore'"` を実行する（OPPO の端末では `adb shell pm clear` が `CLEAR_APP_USER_DATA` の権限で拒まれた。[テスト結果](テスト結果.md) 2.1）
- 本物の鍵のリリース版に入れ替えるときは、鍵が違うので上から入れられず、一度アンインストールが要る（データは消える）。手順は [リリース 基本設計](../リリース/基本設計.md)

### 5.3 7.2 シナリオ通し（US-01〜06）

デバッグ版でよい（⑤ で戻した状態）。端末の Android の版を最初に書く。

| No | シナリオ | 手順 | 期待 |
|---|---|---|---|
| S-1 | US-01 思いついたことをメモする | 起動 → ＋ → 本文を入力 → ✓ → ← | 一覧の先頭に出る。本文が空のときは ✓ が押せない |
| S-2 | US-01 例外 | 書きかけで ← → 「キャンセル」→ もう一度 ← →「破棄」 | キャンセルで編集を続け、破棄で一覧に戻り保存されない |
| S-3 | US-02 見返す | 一覧のメモを押す | 1 行目と更新日時が新しい順に並び、押すと全文が出る |
| S-4 | US-03 書き直す | メモを開いて直す → 横向きにする → 縦に戻す → ✓ → ← | 回転しても入力が消えない。更新日時が変わり、一覧で先頭に来る |
| S-5 | US-04 消す | メモを開く → ⋮ →「削除」→「キャンセル」→ もう一度「削除」→「削除」 | キャンセルでは残り、削除で一覧から消える |
| S-6 | US-05 残っている | 保存後、最近使ったアプリから消す → 開く。スマホを再起動 → 開く | どちらでもメモが残る |
| S-7 | US-06 書きかけが戻る | 開発者向けオプション「アクティビティを保持しない」をオン → 書きかけでホームへ → アイコンから戻る（終わったらオフに戻す） | 書きかけの入った編集画面に戻る |
| S-8 | US-06 実際の中断 | 書きかけのまま電話を受ける、またはほかの重いアプリ（カメラ・ゲーム等）をしばらく使ってから戻る | 書きかけが戻る（システムに終了されていなければ、そのまま残っている） |
| S-9 | US-06 例外 | 書きかけのまま最近使ったアプリから消す → 開く | 一覧が開き、書きかけは残らない |
