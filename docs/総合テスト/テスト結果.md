## 2. 実機での実施結果（2026-11-15〜16、開発者と Claude）

**端末**: OPPO CPH2099（Android 11、API 30）、1080×2400、60Hz。USB で PC につなぎ、開発者が画面を触り、Claude が PC からコマンドを実行した。この端末には SinMemo が入っていなかった（ユーザーのメモはなし）。

### 2.1 進め方で起きたこと
| 起きたこと | 対応 |
|---|---|
| `seed` が、一度もアプリを開いていない（`databases` フォルダがない）とき `ls` の失敗で止まった。予行のエミュレータには DB があり、試せていなかった | スクリプトを直した（`ls databases 2>/dev/null; true`）。直した後の `seed` は「端末に DB がまだない」と出て進んだ |
| `seed` で入れた DB の権限が `rw-rw-rw-`（`/data/local/tmp` から写したため） | アプリが作るときと同じ `rw-rw----`（660）にするようスクリプトを直した。アプリのフォルダは他のアプリから入れないので、直す前も読まれることはない |
| PC からのタップ・スワイプの送り込み（`adb shell input`）が `INJECT_EVENTS permission` で拒まれた | OPPO は開発者向けオプションの「USB デバッグ（セキュリティ設定）」が要る。設定は変えず、画面の操作はすべて開発者が行った |
| `adb shell pm clear` が `CLEAR_APP_USER_DATA` で拒まれた | デバッグ版で `run-as` を使い、`databases` と `files/datastore` を消した（[テスト設計](テスト設計.md) 5.2 ⑤ に追記） |
| 1 回目のスクロールの記録は、開発者がアプリを最近使ったアプリから消したため数値が消えた | 記録をリセットし直し、アプリを開いたまま開発者がスクロールして取り直した |

## 6. 7.4（#59）攻撃役の指摘による修正（2026-11-16、Claude）
各機能のテスト設計に足した自動テスト（C-U-18〜36、L-U-31〜44、E-U-53〜74、DR-U-15〜23、ST-U-44〜55、RL-U-02・03）とビルドの確認（RL-B-11〜26）の結果を、ここにまとめて書く。クラウドの作業環境（Linux、エミュレータ・実機なし）で行った。

### 6.1 進め方
設計役 → 実装役 → 確認役・攻撃役 → 実装役（指摘の修正）の順に、Claude のサブエージェントで進めた。

| 役 | 結果 |
|---|---|
| 確認役 | 重大な指摘なし。中 1 件（同じ設定の知らせが続くと 2 つ目のトーストが出ない）、低 5 件（失敗の帯の出し直し、E-U-61 の書き方、手順の表の書き方、RL-B-16 の用意の失敗 など）。直した |
| 攻撃役 | データが失われる穴なし。中 2 件（保存・削除の「閉じた」印を付ける時期が遅く、裏に回ったあとに保存が終わると残らない／Android 11 以下の機種変更でメモと設定が移らない）、低 4 件（一覧の読み込みが一度失敗すると止まる、`RECEIVER_NOT_EXPORTED` を見張るテストがない、`.env` の `export `・重複などを黙って読み飛ばす、同じ知らせが続くとき）。直した。実装を 20 通り壊してテストを流し、18 通りを捕まえた（残り 2 通りのうち 1 通りは動きが変わらない変更、もう 1 通りは C-U-36 を足して捕まえた） |
