## 2. 設定の値（データ層）

| 型 | 種類 | 値・項目 |
|---|---|---|
| `ThemeMode` | enum | `SYSTEM`／`LIGHT`／`DARK` |
| `FontSizeSetting` | enum | `SMALL`／`MEDIUM`／`LARGE` |
| `UserSettings` | data class | `themeMode`（初期値 `LIGHT`）、`fontSize`（初期値 `MEDIUM`） |

- 文字サイズの値（sp）は画面の都合なので UI 層の `FontSize`（[共通 基本設計](../共通/基本設計.md) の表の値）に置き、データ層は「小・中・大」のどれかだけを持つ（決定事項 5）。変換は `FontSize.from(setting)`
- テーマの解決 `ThemeMode.isDark(systemDark: Boolean)`: `ThemeMode` と「端末がダークか」から、ダークで描くかを返す純粋な関数（単体テストのため）

## 3. 保存（DataStore）

[共通 詳細設計](../共通/詳細設計.md) の DataStore の決めごとのとおり。値は enum の名前で保存する。

| キー | 型 | 値 | 初期値 |
|---|---|---|---|
| `theme_mode` | String | `SYSTEM`／`LIGHT`／`DARK` | `LIGHT` |
| `font_size` | String | `SMALL`／`MEDIUM`／`LARGE` | `MEDIUM` |

- ファイル: `settings.preferences_pb`（アプリの `files/datastore/` の下。→ 2026-11-17 からバックアップしない。[共通 詳細設計](../共通/詳細設計.md) 13.5）
- 値が無い・知らない値・型が違う値は初期値として扱う。項目ごとに判定する
- 読み込みで `IOException`（ファイルが壊れている等）が出たら、初期値で続ける。書き込みの失敗は表示に出さない。→ 7.4 で変える（10 章）。今の `catch` は流れを止めてしまい、後の保存が反映されなかった。壊れたファイルは `corruptionHandler` で上書きし、ほかの `IOException` は読み直す
- DataStore はアプリで 1 つだけ作る（同じファイルに 2 つ作ると例外になる）。Hilt の `SingletonComponent` で提供する

## 5. アプリ全体への反映（MainViewModel・MainActivity・SinMemoApp）

| 部品 | 内容 |
|---|---|
| `MainViewModel`（`@HiltViewModel`） | `settings: StateFlow<UserSettings?>`。リポジトリの `settings` を `stateIn(SharingStarted.Eagerly, null)` で持つ。読み終わるまでは null |
| `MainActivity` | 6 章のスプラッシュの処理のあと、`setContent` で `settings` が null の間は何も描かない。`ThemeMode.isDark(isSystemInDarkTheme())` を 1 回だけ求め、`SinMemoApp` とシステムバーの両方に使う |
| システムバーのアイコン色 | ダークで描くかが変わるたびに `enableEdgeToEdge` を呼び直す |
| `SinMemoApp(darkTheme, fontSize, content)` | `SinMemoTheme(darkTheme)` と `CompositionLocalProvider(LocalFontSize provides FontSize.from(fontSize))` で包む。`fontSize` は設定の値（`FontSizeSetting`）で受け取り、sp への変換はここで行う。`content` は既定で NavHost |
| 背景 | `SinMemoApp` で画面全体をテーマの背景色の `Surface` で塗る（決定事項 4） |
| 一覧・編集 | `MemoListScreen`・`MemoEditScreen` は `LocalFontSize.current` を読み、`MemoListContent`・`MemoEditContent` へ引数で渡す（Content は引数で受け取るまま。UI テストで好きな値を渡せるように） |

流れ:
- 設定はアプリ全体で 1 か所（`MainActivity` の `MainViewModel`）で読む
- 設定が変わる → `settings` に新しい値 → `MainActivity` が描き直す → テーマは `SinMemoTheme` へ、文字サイズは `LocalFontSize` で各画面へ

## 6. スプラッシュ（基本設計 5 章）

| 項目 | 作り方 |
|---|---|
| ライブラリ | `androidx.core:core-splashscreen`（Android 10・11 でも Android 12 以降と同じ見た目で出す） |
| 起動用テーマ | `res/values/themes.xml` の `Theme.SinMemo.Starting`（親 `Theme.SplashScreen`）。背景 `windowSplashScreenBackground` = 白、アイコン `windowSplashScreenAnimatedIcon` = `@drawable/ic_launcher_foreground`、`postSplashScreenTheme` で `Theme.SinMemo` に戻す。マニフェストの Activity の `android:theme` に付ける |
| 出し続ける | `MainActivity` で `installSplashScreen()`（`super.onCreate` より前）→ `setKeepOnScreenCondition` に `SplashGate` の判定を渡す |
| 消え方 | `setOnExitAnimationListener` で 0.2 秒のフェードアウト |
| 時間の測り方 | `SystemClock.elapsedRealtime()`。起動時刻は `onCreate` で取る |
| 新しい起動か | `savedInstanceState == null` のときだけ最小表示時間をかける |

`SplashGate`（Android に依存しない判定）

| 部分 | 内容 |
|---|---|
| 作るときに渡す | 起動時刻 `startMillis`、最小表示時間をかけるか `applyMinimum`（新しい起動なら true） |
| `shouldKeepOnScreen(今の時刻, 読み終わったか)` | スプラッシュを出し続けるか |
| 定数 | `FADE_OUT_MILLIS` など（下） |

- 読み終わっていなければ出し続ける。新しい起動なら、読み終わっても起動から 500 ミリ秒未満は出し続ける。500 ミリ秒ちょうど以降、または新しい起動でなければ、読み終わり次第消す
- 定数: 最小 500 ミリ秒、フェード 200 ミリ秒

## 10. 7.4 で変えるところ（Issue #59）

[基本設計](基本設計.md) 8 章の作り方。

### 10.1 部品の分担

| 部品 | 7.4 での役目 |
|---|---|
| `DataStoreModule` | DataStore を作るときに `corruptionHandler` を渡す（10.2） |
| `SettingsResetFlag`（新しい。`data/settings/`） | 「壊れたファイルを初期値で上書きした」印（10.2） |
| `DataStoreSettingsRepository` | 読み込みの一時的な失敗を読み直す（10.3）。上書きの印を外に見せる |
| `MainViewModel` | 3 秒の打ち切り、遅れて読めたときの切り替え、メッセージの順番待ち（10.4） |
| `MainActivity` | メッセージをトーストで出す（10.5） |
| `SettingsViewModel` | 保存の失敗を受け止める（10.6） |

### 10.2 壊れたファイルの上書き（#59 決定 9）

- `SettingsResetFlag`（`@Singleton class SettingsResetFlag @Inject constructor()`）
  - `val wasReset: StateFlow<Boolean>`（初期値 false）
  - `fun markReset()`: true にする
  - `fun clear()`: false に戻す
- `DataStoreModule.provideSettingsDataStore(context, flag)` で作る
  - `PreferenceDataStoreFactory.create(corruptionHandler = ReplaceFileCorruptionHandler { flag.markReset(); emptyPreferences() }, produceFile = { context.preferencesDataStoreFile(FILE_NAME) })`
  - `ReplaceFileCorruptionHandler` は、壊れたファイル（`CorruptionException`）を見つけたとき、返した値（空 = 初期値）を**ファイルに書いてから**読み込みを続ける。次の起動では壊れていない
  - テストでも同じ作り方を使えるよう、中身を `internal fun createSettingsDataStore(produceFile: () -> File, scope: CoroutineScope, flag: SettingsResetFlag): DataStore<Preferences>` に出す（テストは一時フォルダのファイルとテストの scope を渡す）
- `SettingsRepository` に足す
  - `val wasReset: StateFlow<Boolean>`（`DataStoreSettingsRepository` は `flag.wasReset` をそのまま返す）
  - `fun clearResetNotice()`（`flag.clear()`）
- `FakeSettingsRepository` も同じものを持つ（テストから true にできる）

### 10.3 読み込みの一時的な失敗の読み直し（#59 その他。設計役の案）

`DataStoreSettingsRepository.settings` の流れを次に変える。

| 順 | 今 | 7.4 |
|---|---|---|
| 1 | `dataStore.data` | 同じ |
| 2 | `.catch { e -> if (e is IOException) emit(emptyPreferences()) else throw e }` | **`.retryWhen { cause, attempt -> if (cause is IOException) { delay(retryDelay(attempt)); true } else false }`**。初期値は流さない |
| 3 | `.map { ... }`・`.distinctUntilChanged()` | 同じ |

- `retryDelay(attempt)` = `min(500L * (attempt + 1), 5_000L)` ミリ秒（0.5 秒、1 秒、1.5 秒…最大 5 秒。設計役の案）。読み直しは購読している間ずっと続ける
- 壊れたファイル（`CorruptionException`）は 10.2 の `corruptionHandler` が先に処理するので、ここには来ない（上書きの書き込みが失敗したときだけ `IOException` として来て、読み直す）
- 初期値を流さないのは、「読めないときに初期値で開く」を `MainViewModel` の 3 秒の打ち切り（10.4）に任せ、メッセージを出すため
- `SettingsViewModel` は今までどおり `stateIn(..., UserSettings())` なので、読めるまで初期値で表示される

### 10.4 `MainViewModel`（#59 決定 7・9・10）

| メンバー | 今 | 7.4 |
|---|---|---|
| `settings: StateFlow<UserSettings?>` | `repository.settings.stateIn(Eagerly, null)` | 中身を `MutableStateFlow<UserSettings?>(null)` にして、下の 2 つのコルーチンで書く |
| `notices: StateFlow<List<QueuedNotice>>`（新しい） | - | 出すメッセージの順番待ち。`QueuedNotice(id, notice)` は起きた順の通し番号付き（7.4 の確認で番号を足した）。初期値は空 |
| `onNoticeShown(id)`（新しい） | - | `notices` からその番号の 1 つを外す |

`init` で `viewModelScope.launch` を 3 つ動かす。
1. **読み込み**: `repository.settings.collect { _settings.value = it }`（遅れて読めた値・後の変更も、そのまま入る。決定 10）。`try` で包み、`CancellationException` は投げ直し、それ以外の `Exception`（リポジトリが読み直さない、`IOException` 以外の失敗）は `Log.w` に種類だけを出して、2 と同じ `useDefaultsWithNotice()`（まだ null なら初期値にして `LoadTimeout` を足す）を呼ぶ。すでに値があれば何もしない（二重に出さない。開発者の決定（2026-11-17））
2. **3 秒の打ち切り**: `delay(SETTINGS_LOAD_TIMEOUT_MILLIS)`（3,000）→ `useDefaultsWithNotice()`: `_settings.value` がまだ null なら、`_settings.value = UserSettings()` にして `notices` の後ろに `SettingsNotice.LoadTimeout` を足す（`compareAndSet(null, UserSettings())` で、1 と同時に来ても読めた値を上書きしない）
3. **上書きの知らせ**: `repository.wasReset.filter { it }.collect { notices に SettingsNotice.Reset を足す; repository.clearResetNotice() }`

`SettingsNotice`（`MainViewModel.kt` に置く enum）

| 値 | 文字列のキー | 文 |
|---|---|---|
| `LoadTimeout` | `settings_load_timeout` | 設定を読み込めませんでした。初期値で表示します |
| `Reset` | `settings_reset` | 設定を初期値に戻しました |

- `SplashGate` は変えない。3 秒たつと `settings` が初期値になるので、スプラッシュが消える
- 「一度だけ」: `Reset` は印を外してから足すので、同じ起動の中で 2 度足されない。メッセージを出したら `onNoticeShown` で外すので、画面を回転しても出し直さない（`MainViewModel` は回転では作り直されない）。ファイルは上書き済みなので次の起動でも出ない
- 定数 `SETTINGS_LOAD_TIMEOUT_MILLIS = 3_000L` は `MainViewModel` の `companion object` に置く。テストでは `runTest` の仮想の時間で進める

### 10.5 `MainActivity` のメッセージ（設計役の案）

- `setContent` の中（`settings` が null でなくなった後）で `viewModel.notices` を `collectAsStateWithLifecycle()` で見る
- 出し方は `MainActivity.kt` の `SettingsNoticeToasts(notices, onShown)`（テストできるように分けた composable）。`LaunchedEffect(先頭の通し番号)` で、先頭があれば `Toast.makeText(context, 文, Toast.LENGTH_LONG).show()`（文は `stringResource` で先に取り出す。`LocalContext` から文字列を引くと lint が画面の設定の変化に追従しないと指摘するため） → `viewModel.onNoticeShown(先頭の番号)`。先頭が外れると次の 1 つが出る（トーストは Android が順に出す）
- 鍵を通し番号にする理由: 種類（`SettingsNotice`）を鍵にすると、同じ種類が続いたとき（[Reset, Reset]）先頭が外れても鍵が変わらず、2 つ目が出ない（7.4 の確認役の指摘）

### 10.6 保存の失敗（`SettingsViewModel.onDialogConfirm`。#59 決定 1）

- 読み込みの失敗: `settings` の `stateIn` の前に `catch`（`CancellationException` は投げ直し、`Log.w` だけ）を入れ、`IOException` 以外の失敗でも落とさず初期値で表示する（開発者の決定（2026-11-17））
- `viewModelScope.launch` の中の `setThemeMode`／`setFontSize` を `try` で包み、`CancellationException` は投げ直し、`Exception` は `Log.w(TAG, "設定を保存できなかった: ${e::class.simpleName}")` だけにする
- 表示は変えない（保存されなかったので `settings` は元の値のまま流れない）。ダイアログは今までどおり先に閉じている
- 壊れたファイルのまま「OK」を押すと落ちていた原因は `corruptionHandler` がないことだった（`edit` が `CorruptionException` を投げた）。10.2 で直り、10.6 は残りの失敗（記憶装置の一時的なエラー）への備え

## 決定事項（2026-11-12）

| No | 論点 | 決定 | 理由・経緯 |
