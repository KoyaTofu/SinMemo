## 2. 守るもの

| 資産 | 置き場所 | 失うと |
|---|---|---|
| メモの本文 | DB `sinmemo.db`（アプリ専用の領域） | 秘密が漏れる（パスワードや個人的なことを書く人もいる） |
| 書きかけ（下書き） | 画面の状態（SavedStateHandle。システムが保持） | 同上 |
| メモがあること自体 | DB | 消される・書き換えられると困る |
| 設定 | DataStore `settings.preferences_pb` | 見た目が変わるだけ（価値は低い） |
| 署名鍵（[リリース](../リリース/基本設計.md) で作る） | 開発者の PC | 偽のアップデートを配られる |

## 3. 攻撃者と狙い

| No | 攻撃者 | できること | 狙い |
|---|---|---|---|
| T1 | 同じ端末の悪意あるアプリ（普通の権限だけ） | Intent を送る、自分の画面を出す | メモを読む・消す、アプリを落とす、偽の画面でだます |
| T2 | 同じ端末の悪意あるアプリ（ユーザーが特別な権限を許可） | 他のアプリの上に重ねて表示、画面の録画、ユーザー補助 | タップをだまし取る、画面からメモを読む |
| T3 | 端末を手にした人 | 画面を見る、USB でつなぐ | メモを読む |
| T4 | バックアップ・機種変更の経路 | Google のバックアップ、`adb backup` | メモを読む |
| T5 | ネットワーク上の攻撃者 | 通信の盗み見・改ざん | メモを読む |
| T6 | 開発・配布の経路 | ライブラリ・ビルド道具の改ざん、リポジトリの秘密 | アプリに悪いコードを入れる |

## 4. 攻撃面と攻撃のシナリオ

### 4.1 攻撃面（外から触れられる所）の調べ方

リリース版の APK（`./gradlew assembleRelease`）とマージ後のマニフェストで、次を確かめる。

| 項目 | 調べ方 |
|---|---|
| 要求する権限（特に `INTERNET`） | マージ後のマニフェスト、`aapt2 dump badging` |
| 外部に公開している部品・公開していない部品 | マージ後のマニフェストの `exported` |
| ContentProvider・FileProvider・WebView・PendingIntent | マニフェストとソースの検索 |
| リリース版のデバッグ可否 | `aapt2 dump badging` に `application-debuggable` が出ないこと |
| `allowBackup` | マニフェスト（[共通 基本設計](../共通/基本設計.md) の決定と同じか） |
| ログ出力 | アプリのコードの `Log`・`println` の検索 |
| 生の SQL | `@Query` の引数バインド以外がないか |
| 秘密情報 | リポジトリと全履歴の `git grep`・差分の検索。`.env`・`local.properties` が `.gitignore` 済みか |

### 4.2 攻撃のシナリオと検証の方法

環境: U = 自動テスト（PC、Robolectric）、K = 構成・設定の確認（PC で手で）、E = エミュレータ、D = 実機

| No | 攻撃者 | 攻撃の手段 | 狙い | 検証の方法 | 環境 |
|---|---|---|---|---|---|
| A-1 | T1 | Navigation の「明示的ディープリンク」の extras（`deepLinkIds`・`deepLinkArgs`）を付けて `MainActivity` を起動し、指定したメモの編集画面を直接開かせる | ユーザーの知らないうちに画面を操作させる。他の攻撃（A-9 等）の足がかり | 攻撃を再現（`SecurityTest`）。比較として自分のアプリからなら開くこと、`EXTRA_REFERRER_NAME` で呼び出し元を偽った場合も確認 | U |
| A-2 | T1 | 型の違う・存在しない値を extras に入れて起動 | アプリを落とし続ける（使えなくする） | `SecurityTest.malformedExtras_doNotCrash` | U |
| A-3 | T1 | 他のアプリが DB・設定のファイルを直接読む | メモを読む | 構成の確認（置き場所） | K |
| A-4 | T1 | ContentProvider・Service・Receiver を呼ぶ | メモを読む・消す | マージ後のマニフェスト | K |
| A-5 | T1 | クリップボードを読む | コピーしたメモを読む | 構成の確認（アプリがクリップボードに書くか、Android の仕様） | K |

| A-7 | T1 | 巨大な文字列を貼り付ける | 固まらせる・落とす | メモ編集の自動テスト（上限 10,000 文字。[メモ編集 テスト設計](../メモ編集/テスト設計.md)） | U |

| A-10 | T2・T3 | スクリーンショット・画面録画・「最近使ったアプリ」のサムネイル | 画面からメモを読む | `FLAG_SECURE` を確認（`SecurityTest.weakness_V02_screenIsNotSecure`） | U |

## 5. 環境ごとの確認

### 5.1 自動テスト（PC、Robolectric）

| テストクラス | テスト | 対応 | 確認すること |
|---|---|---|---|
| `SecurityTest` | `deepLinkFromOtherApp_isIgnored`・`deepLinkWithSpoofedReferrer_isIgnored`、比較の `control_deepLinkFromOwnApp_opensEditScreen` | A-1 | 他のアプリからの明示的ディープリンクは無視され一覧が開く。呼び出し元の偽装も無視。自分のアプリからなら同じ Intent で開く |
| `SecurityTest` | `malformedExtras_doNotCrash` | A-2 | 壊れた extras で落ちない |
| `SqlInjectionTest` | `sqlInBody_isStoredAsText_andTableSurvives`・`sqlInUpdate_changesOnlyThatMemo` | A-6 | 本文の SQL が文字として保存され、表も他のメモも残る |
| `SecurityTest` | `weakness_V01_obscuredTouch_isAccepted` | A-9（V-01） | 受け入れた弱点の記録。印付きのタップを受け付けること（対策したら期待値を逆にする） |
| `SecurityTest` | `weakness_V02_screenIsNotSecure` | A-10（V-02） | 受け入れた弱点の記録。`FLAG_SECURE` がないこと（対策したら期待値を逆にする） |
| `SecurityTest` | `V03_mainActivity_hasEmptyTaskAffinity` | C-1（A-11 の対策） | 下の 5.2 |
| `BuildIntegrityTest` | `gradleDistribution_isPinnedByOfficialSha256` | C-2（A-15 の対策） | 下の 5.2 |

**試験のしかたで気をつけること**
- **「攻撃が効かなかった」テストは、比較の試験と組にする**（A-1）。自分のアプリからなら同じ Intent で編集画面が開くことを確かめ、攻撃の作り方が間違っていて弾かれただけ、ではないことを示す
- **画面が描かれるまで待ってから判定する**。設定（DataStore）を別のスレッドで読み終わるまで画面は空なので、待たないと「秘密が出ていない」が何も出ていないだけで通ってしまう。タップの時刻は今の時計から作る（→ 最初は待ちがなく、全テストと一緒に流すと V-01 のテストが失敗したため、こう変えた）
- テストは `--rerun` を付けて実行する（付けないと Gradle は変更がなければテストを実行せず、前回の結果を使う。[テスト結果](テスト結果.md) 6 章）

### 5.2 対策の確認（V-03・A-15）

| No | テスト | 確認すること | 環境 |
|---|---|---|---|
| C-1 | `SecurityTest.V03_mainActivity_hasEmptyTaskAffinity` | `MainActivity` の taskAffinity がパッケージ名でなく、空（Android の中では null） | U |
| C-2 | `BuildIntegrityTest.gradleDistribution_isPinnedByOfficialSha256` | `distributionUrl` が 9.9.1 で、`distributionSha256Sum` が公式の値。Gradle を上げたのにハッシュを直し忘れると失敗する | U |
| C-3 | APK のマニフェスト（`aapt2 dump xmltree`） | デバッグ版・リリース版とも `android:taskAffinity=""` が入っている | K |
| C-4 | 違うハッシュで Gradle を取らせる（手で実施） | 先頭 4 文字を `0000` にした wrapper を、空の `GRADLE_USER_HOME` で動かすと拒む | K |
| C-5 | 正しいハッシュで Gradle を取らせる（手で実施） | リポジトリの `gradle-wrapper.properties` で、空の `GRADLE_USER_HOME` から取得して動く | K |

- 公式の値の照合: `gradle-<版>-bin.zip` と公式の `.sha256` を services.gradle.org から取り、手元で計算した値と比べる
- C-4・C-5 の注意: Gradle は ZIP を**ダウンロードしたときだけ**照合する。手元の `~/.gradle/wrapper/dists` に展開済みのものがあると照合しないので、wrapper 一式をスクラッチパッドに複写し、空の `GRADLE_USER_HOME` で `gradlew --version` を実行する
- **壊す確認**: マニフェストから `taskAffinity=""` を一時的に消すと C-1 が失敗すること

### 5.3 エミュレータ

攻撃役のアプリ（`com.example.attacker`）をスクラッチパッドで作って入れる（Java の Activity 2 つだけ。リポジトリには入れない。確認後にアンインストールする）。作るときの注意は [作業メモ](../記録/作業メモ.md)（2026-11-15）。

| 攻撃役の部品 | 中身 |
|---|---|
| `FakeActivity` | `taskAffinity="com.example.sinmemo"`（SinMemo の対策前の既定値）を名乗る偽の画面。「FAKE SinMemo (attacker)」と出す |
| `OverlayActivity` | 「他のアプリの上に重ねて表示」で、画面全体に半透明の窓を出す。タッチは下へ通す（`FLAG_NOT_TOUCHABLE`）。許可は `appops set com.example.attacker SYSTEM_ALERT_WINDOW allow` で与える（ユーザーが設定で許可した状態） |

| No | 試すこと | 期待 |
|---|---|---|
| A-11 | 攻撃役が `FakeActivity` を開いてホームへ戻る → ユーザーがランチャーから SinMemo を開く（`monkey -c LAUNCHER`）。比較として `taskAffinity=""` を一時的に外した版でも試す | 対策ありでは SinMemo の一覧が開く。外した版では偽の画面が出る（攻撃の作り方が正しいことの確認） |
| V-01 | SinMemo の一覧の上に攻撃役の窓を重ね、FAB の位置を押す（`input tap`） | Android 10 では窓の下に届く（受け入れた弱点のとおり） |
| A-13 | `adb shell run-as com.example.sinmemo` で DB を読む（デバッグ版と、デバッグ用の鍵で署名し直したリリース版） | デバッグ版は読める。リリース版は `package not debuggable` で拒まれる |
