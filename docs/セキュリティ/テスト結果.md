## 1. 結論（2026-11-13 の検証）

対象: main の efaa0c2（WBS 6 まで）。版 0.1.0。件数は対策前（検証したとき）のもの。

| 判定 | 件数 | 内容 |
|---|---|---|
| 防げる | 8 | 他のアプリからの読み取り・画面の直接起動・壊れたデータによる強制終了・SQL インジェクション・ネットワークへの持ち出し など |
| 一部防げる／条件付き | 5 | クリップボード、バックアップ、デバッグ版、端末を手にした人、ビルドの改ざん |
| 防げない（対策を提案） | 3 | **V-01 タップジャッキング（Android 10・11）**、**V-02 画面に写る**、**V-03 タスクの乗っ取り** |
| 対象外 | 2 | 端末の管理者権限（root）・悪意あるユーザー補助サービス |

- **重大な弱点（遠隔から、または他のアプリが権限なしでメモを読む・消す）は見つからなかった**
- 一番効いているのは「インターネットの権限がない」こと。万一アプリの中に悪いコードが入っても、メモを外へ送れない
- 対策は開発者が決めた（[基本設計](基本設計.md)）。V-03 と Gradle のハッシュ照合を入れ、V-01・V-02 は受け入れる
- **2026-11-15: V-03 と A-15（Gradle のハッシュ照合）の対策を入れ、テストで確かめた（4 章）。エミュレータで A-11・V-01・A-13 を確かめた（5 章）**

## 2. 攻撃面（外から触れられる所）

リリース版の APK（`./gradlew assembleRelease`）とマージ後のマニフェストで確かめた。

| 項目 | 結果 |
|---|---|
| 要求する権限 | `com.example.sinmemo.DYNAMIC_RECEIVER_NOT_EXPORTED_PERMISSION` のみ（androidx が自動で付ける、自分のアプリ専用のもの）。**`INTERNET` なし** |
| 外部に公開している部品 | `MainActivity`（起動用。必須）、`androidx.profileinstaller.ProfileInstallReceiver`（`android.permission.DUMP` が必要 = シェルとシステムしか呼べない） |
| 公開していない部品 | `androidx.startup.InitializationProvider`、Room の `MultiInstanceInvalidationService`（`exported=false`） |
| ContentProvider・FileProvider・WebView・PendingIntent | なし |
| リリース版のデバッグ可否 | 不可（`aapt2 dump badging` に `application-debuggable` が出ない）。デバッグ版は可 |
| `allowBackup` | `true`。除外の指定なし（[共通 基本設計](../共通/基本設計.md) で決めたとおり） |
| ログ出力 | アプリのコードに `Log`・`println` なし |
| 生の SQL | なし（`@Query` の引数バインドのみ） |
| 秘密情報 | リポジトリと全履歴（50 コミット）に、パスワード・API キーらしき文字列なし。`.env`・`local.properties` は `.gitignore` 済み |

## 3. 検証の結果（2026-11-13）

| No | 判定 | 結果・根拠 |
|---|---|---|
| A-1 | ◎ | 他のアプリからは**無視され一覧が開く**。偽装も無視。Navigation 2.10.2 が呼び出し元を確かめている（`NavController.shouldTrustIntent`: 呼び出し元が自分のパッケージのときだけ受け付け、REFERRER の extras があれば拒否。ライブラリのバイトコードで確認）。比較: 自分のアプリからなら開く（= 攻撃の作り方は正しい） |
| A-2 | ◎ | 落ちずに一覧が開く。アプリのコードは Intent の中身を読まない |
| A-3 | ◎ | ファイルはアプリ専用の領域（`/data/data/com.example.sinmemo`。Android のアプリごとのユーザー ID で分けられ、他のアプリは読めない）。外部ストレージには書いていない |
| A-4 | ◎ | 公開している Provider・Service はない。Receiver は DUMP 権限が必要（2 章） |
| A-5 | ○ | アプリはクリップボードに自分から書かない。ユーザーがコピーした場合、Android 10 以降は裏にいるアプリはクリップボードを読めない（前面のアプリと入力中のキーボードだけ）。Android 12 以降は読まれると通知が出る |
| A-6 | ◎ | SQL は文字として保存され、表も他のメモも残る。Room は引数をバインドする |
| A-7 | ◎ | 上限を超える貼り付けは取り消す（[メモ編集 基本設計](../メモ編集/基本設計.md) の文字数の上限） |
| A-8 | ◎ | `INTERNET` 権限がなく、通信そのものができない |
| A-9 | × **V-01** | 印付きのタップも受け付けて画面が反応した。Android 12 以降は OS が信頼できない重ね表示のタップを止めるが、**Android 10・11（minSdk 29・30）では止まらない**。重ねて表示するにはユーザーの許可（「他のアプリの上に重ねて表示」）が必要なので、起きる可能性は低い。読まれることはない（消される・捨てさせられる）。→ 受け入れた（[基本設計](基本設計.md) 決定事項 1） |
| A-10 | × **V-02** | `FLAG_SECURE` がないので写る。録画にはユーザーの許可が必要。サムネイルは肩越しに見られる程度。→ 受け入れた（[基本設計](基本設計.md) 決定事項 2） |
| A-11 | × **V-03** | `MainActivity` に `taskAffinity` の指定がなく、既定（パッケージ名）のまま。Android の版によって影響が残るとされる。メモアプリで偽の画面から得られるものは少ないので、起きる可能性も影響も低い。**→ 2026-11-15 対策済み（`taskAffinity=""`。4 章・5 章）** |
| A-12 | ○ | 自動バックアップの対象（[共通 基本設計](../共通/基本設計.md) で決定）。クラウドバックアップは、端末に画面ロックがあれば端末側で暗号化される（Android 9 以降）。`adb backup` は、targetSdk 31 以降のアプリでは**リリース版のデータを含まない**（デバッグ版は含む） |
| A-13 | ○ | **リリース版は不可**。デバッグ版は `application-debuggable` なので、開発者向けオプションの USB デバッグが有効で PC を許可していれば読める。今の端末にはデバッグ版が入っている想定なので、リリース版に入れ替える（[リリース 基本設計](../リリース/基本設計.md) のインストールの手順）までは注意 |
| A-14 | ○ | アプリにパスワード・生体認証のロックはない（要件にない）。端末の画面ロックに頼る。ロック中の端末では、DB は資格情報で暗号化された領域（CE ストレージ）にあり、一度もロックを解除していない状態では読めない |
| A-15 | ○ | `gradle-wrapper.jar` の SHA-256（`621008af…`）は公式（services.gradle.org）と一致。ただし Gradle 本体の ZIP をダウンロードするときの照合値（`distributionSha256Sum`）が未設定。ライブラリは Google Maven（`com.android`・`com.google`・`androidx` に限定）と Maven Central から取り、照合ファイル（`verification-metadata.xml`）はない。悪いコードが入っても A-8 のとおり外へ送れない。**→ 2026-11-15 `distributionSha256Sum` を設定（4 章）。ライブラリの照合ファイルは未対応のまま** |
| A-16 | ◎ | 見つからず。署名鍵はリポジトリに入れない方針（[スケジュール](../記録/スケジュール.md) 8.1、[リリース 基本設計](../リリース/基本設計.md)） |
| A-17 | − | アプリでは防げない（OS の守りの外）。DB は暗号化していない |
| A-18 | − | アプリでは防げない。Android は有効にするときに強い警告を出す |

- 自動テスト（A-1・A-2・A-6・A-9・A-10）は `--rerun` を付けて 3 回実行し、毎回 148 件成功を確認した（単体テスト全体の件数）
- 途中で起きた問題: 最初は画面が描かれるまで待たずに判定していて、全テストと一緒に流すと V-01 のテストが失敗した。待つように直し、タップの時刻も今の時計から作るよう直した（[テスト設計](テスト設計.md) 5.1）

## 6. 記録の誤りの訂正（2026-11-13）

検証中に、設定のテスト（WBS 6.3）の記録に誤りを見つけた。
- 6.3 で「直さずに 6 回、壊した状態で 2 回やり直しても再現しなかった」「直した後 5 回続けて成功」と書いたが、同じコマンドを繰り返しただけで、**2 回目以降は Gradle がテストを実行していなかった**（ログに `testDebugUnitTest UP-TO-DATE`）
- `--rerun` を付けて `SettingsFlowTest` を 5 回実行し、5 回とも成功したことを確かめた。壊す確認（8 通り）は毎回コードを変えていたので実行されており、結果は有効
- 元の記録（「途中で起きた問題と対応」）は直した。直した後の記録は [設定 テスト結果](../設定/テスト結果.md)
- これ以降、テストは `--rerun` を付けて実行する

- **自動の静的解析**（Android Lint のセキュリティ項目、MobSF 等）は実行していない
- **A-12（バックアップの中身）** は試していない
- **実機（開発者の端末、Android 11）での A-11・V-01** は未確認（Android 12 以降は V-01 を OS が止める）
- **A-13 の本物の鍵のリリース版での確認**は、リリースの実機確認で行う（[リリース テスト設計](../リリース/テスト設計.md)）
- **A-15 のライブラリの照合ファイル**（`verification-metadata.xml`）は未対応
- 端末での確認は、最初の検証（2026-11-13）ではエミュレータ・実機がなく、Robolectric の試験・マニフェスト・Android の公式の仕様を根拠にした → 2026-11-15 に V-01・A-11・A-13 をエミュレータで試した（5 章）
- Gradle 本体の ZIP の照合は、最初は展開後に ZIP が消されていてできなかった → 2026-11-15 にダウンロードし直して照合した（4.1）
