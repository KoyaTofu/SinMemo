## 2026-11-11 要件定義の準備作業（Claude Code、クラウド環境）

### Android SDK の導入
クラウドのコンテナには Android SDK が入っていなかったため、次の手順で導入した（このコンテナ内だけの作業。リポジトリには含まれない）。

1. `commandlinetools-linux-16111833_latest.zip` を dl.google.com から取得し `/opt/android-sdk/cmdline-tools/latest` に展開
2. `sdkmanager --licenses` でライセンスに同意
3. `sdkmanager "platforms;android-37.0" "build-tools;37.0.0" "platform-tools"` を実行
4. ビルド時に AGP が既定の `build-tools;36.0.0` を自動でダウンロードした
5. `local.properties` に `sdk.dir=/opt/android-sdk` を記載（`.gitignore` で除外済み）

### バージョンの選定
2026-11-11 時点で各配布元のメタデータを確認して選んだ。

| 項目 | 採用 | 確認方法 |
|---|---|---|
| Gradle | 9.9.1 | services.gradle.org/versions/current |
| Android Gradle Plugin | 9.5.1 | Google Maven の maven-metadata.xml（alpha/beta/rc を除く最新） |
| Kotlin（Compose Compiler プラグイン） | 2.4.21 | Maven Central の maven-metadata.xml |
| compileSdk / targetSdk | 37 | SDK リポジトリ（repository2-3.xml）。後述 |
| Compose BOM | 2026.09.00 | Google Maven |
| JDK | 21（コンテナ既定） | `java -version` |

- AGP 9 系は Kotlin サポートを内蔵しているため、`org.jetbrains.kotlin.android` プラグインは適用していない（Compose Compiler プラグインのみ適用）
- SDK リポジトリには `platforms;android-37.1`、`android-37.2` という「マイナー版」もある。`targetSdk` は整数しか指定できないため 37 とし、`compileSdk` もわかりやすさを優先して 37（= 37.0）にした。マイナー版で compile するかは要検討

## 2026-11-12 エミュレータの準備（Claude Code、開発者の Windows PC）

開発者の承認を得て、次をダウンロードして入れた（いずれも dl.google.com）。

| 項目 | 内容 |
|---|---|
| Android SDK Command-line Tools | `commandlinetools-win-16111833_latest.zip`（約 148MB）。SHA-1 をリポジトリの値と照合し、`%LOCALAPPDATA%\Android\Sdk\cmdline-tools\latest` に展開 |
| システムイメージ | `system-images;android-29;google_apis;x86_64`（約 1.25GB、展開後 3.1GB）。Android 10（minSdk）で確認するため |
| AVD | `SinMemo_API29`（デバイス定義 `pixel_5`） |

- ハードウェアアクセラレーション: `emulator -accel-check` で WHPX が使えることを確認
- 注意 1: `sdkmanager.bat`・`avdmanager.bat` は cmd.exe 経由で動くため、PowerShell から `system-images;android-29;...` を渡すと `;` で分割されて失敗する（終了コードは 0 になるので気づきにくい）。インストールは新しい Android CLI（`cmdline-tools\latest\bin\android.exe sdk install "..."`）で、AVD 作成は `.cmd` ファイルの中で引数を `"..."` で囲んで実行した
- 注意 2: 既定の GPU 描画ではスクリーンショットが真っ白になる。確認で画像が必要なときは次のように起動する
  ```
  emulator -avd SinMemo_API29 -no-boot-anim -gpu swiftshader_indirect
  ```
  Android Studio の Device Manager からも起動できる（画像が不要なら既定の GPU 描画のほうが速い）

## 2026-11-15 エミュレータでの確認のやり方（Claude Code、開発者の Windows PC）

設定のエミュレータ確認（[設定 テスト結果](../設定/テスト結果.md)）と脆弱性の確認（[セキュリティ テスト結果](../セキュリティ/テスト結果.md)）で使ったやり方。道具はスクラッチパッドに置き、リポジトリには入れていない。

- **画面の操作**: `adb shell uiautomator dump` で部品の文字・説明（content-desc）と位置を取り、`adb shell input tap` で押す。日本語の文字は `adb shell input text` で入らないので、メモの本文は英数字にした
- **スプラッシュ・ちらつきの判定**: 端末の中で `screencap`（PNG にしない生のデータ）を連続で取ると 80〜250 ミリ秒ごとのコマになる。各コマのアプリバーの色・アイコンの青・画面の明るさを Python で数えた。`screencap` を回しながらだと起動は遅めに出る
- **起動時間**: `logcat` の `ActivityTaskManager: Displayed ... +Xms` は最初の画面（スプラッシュを出している Activity の最初の描画）までの時間。一覧が出るまでの時間はコマで見る
- **リリース版を入れる**: `assembleRelease` の未署名 APK を `zipalign` し、`apksigner` でデバッグ用の鍵（`~/.android/debug.keystore`）で署名すると、デバッグ版の上に入れ替えられる（データは残る）。確認後に `installDebug` で戻した
- **攻撃役のアプリ**: スクラッチパッドに別のプロジェクトを作り、このリポジトリの `gradlew.bat -p <フォルダ> assembleDebug --offline` で作った。AGP 9 は Kotlin のプラグインを内蔵していて、指定がないと手元にない版（2.2.10）を取りに行くので、ルートの `plugins` に `org.jetbrains.kotlin.plugin.compose` 2.4.21（SinMemo と同じ・手元にある版）を `apply false` で書いて揃えた
- **画面の回転**: `settings put system accelerometer_rotation 0` のあと `settings put system user_rotation 1`（横）／`0`（縦）
- **端末のダークモード**: `cmd uimode night yes`／`no`
- エミュレータを `adb reboot` すると、端末のタイムゾーンが変わることがある（日時の表示が 5 時間ずれた）
