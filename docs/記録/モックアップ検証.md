モックアップでの割り切り:
- データは画面を開き直すとサンプルに戻る（実際の保存はしない）。「終了して再起動」ボタンでは、保存済みメモ・設定・下書きは残る扱いにしている

- 画面の回転、Android の「戻る」操作（ジェスチャ・戻るボタン）は再現できない。アプリバーの ← で代用

## 2. 検証方法

1. **自動での再現**: プロトタイプの動作ロジックを取り出し、各シナリオの手順（ボタンを押す、文字を入力する等）を順に実行して、画面と状態が期待どおりかを確認した
   ```
   node docs/mockup/verify_scenarios.js docs/mockup/Main.dc.html
   ```
   （v0.1 の手順。v0.2 では 6.4 の `verify_mockup.js` に置き換えた）
2. **目視での確認**（未実施。開発者に依頼）: モックアップを開き、プロトタイプを操作して見た目と使い勝手を確認する

## 4. 検証で見つかった論点

要件で決めていなかった細部を、モックアップでは次のように仮に決めて作った。実装前に決めたい。

| No | 論点 | モックアップでの扱い（案） | 関係する書類 |

### 6.3 GitHub Pages で公開する仕組み
- 今の仕組み（#53 で #36 の形に戻した）: `.github/workflows/mockup-pages.yml` は、`docs/mockup/` かワークフローを変えた PR ではブラウザでの検証（6.4）だけを行い、main への push と手動実行では検証が通ったら **モックアップ 1 枚だけ** を Pages に公開する（`index.html` として置く。ほかの書類・ソースは公開しない）。公開のジョブの権限は `contents: read`・`pages: write`・`id-token: write` だけ
- 準備（開発者）: 公開リポジトリの Settings → Pages → Build and deployment の Source を「GitHub Actions」にする。準備前に main へ push すると、公開のジョブが失敗する（#36 のときと同じ）
- → 2026-11-15 に「検証だけ」にしていた（[スケジュール](スケジュール.md) 決定事項 11・13）
- → #36 では、`docs/mockup/` が main に入るとブラウザでの検証を流し、通ったら **モックアップ 1 枚だけ** を Pages に公開する（`index.html` として置く。設計書・コードは公開しない。PR では検証だけ）仕組みにしていた。準備（開発者）として、リポジトリの Settings → Pages → Build and deployment の Source を「GitHub Actions」にする必要があり、#36 のマージ時は準備前だったため公開の手順が失敗していた。2026-11-15 にリポジトリを非公開のままにすると決めたため、公開の手順を消した。公開するときは #36 の版から公開の手順を戻す
- 注意: Pages は非公開のリポジトリでは有料プラン（GitHub Pro など）が必要。公開したページは、リポジトリが非公開でも誰でも見られる（モックアップには実際のメモや秘密は入っていない）
