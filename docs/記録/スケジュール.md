## 進め方
- **機能ごとに「設計→実装→テスト」を繰り返す**（基盤→一覧→編集→下書き→設定の順）
- **工程ごとに 1 PR**（例: 「一覧の設計」「一覧の実装」「一覧のテスト」で PR 3 本）
  - 設計 PR: `docs/` の設計書（画面・データ・クラス構成）
  - 実装 PR: アプリのコード（ビルドが通ること）
  - テスト PR: 単体テスト・UI テストのコードと、テスト結果の記録
- **担当**: 決定・確認・承認（PR のマージ）は開発者、書類とコードの作成は Claude。実機での確認は開発者
- **進捗の記録**: この表と GitHub Issue の両方。Issue は WBS の 3 桁目（設計・実装・テストの各工程）ごとに 1 件作り、PR と紐づける。Issue は要件定義の PR をマージした後に Claude が作る
- 書類は 2026-11-16 に機能ごとのフォルダへ組み直した（[書類の案内](../README.md)）。下の表の「書類」は組み直したあとの場所。当時の書類は 1 本の設計書（基本・詳細）と、全体で 1 本のテスト記録だった
