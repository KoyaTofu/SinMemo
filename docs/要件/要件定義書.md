## 1. 目的
- シンプルなメモ帳 Android アプリ「SinMemo」を作る
- 主目的は **アプリ開発の一連の流れ（要件定義→設計→実装→テスト→リリース）を学ぶこと**。機能の作り込みより、流れを一通り経験することを優先する
- 副次的な目的: ユーザー（開発者自身）が日常的に使える程度の、最小限のメモ機能を備える

## 2. 範囲

### 2.1 対象
- Android スマートフォン向けのネイティブアプリ（1 アプリ、1 モジュール）
- テキストメモの作成・一覧・編集・削除
- 端末内へのデータ保存（Room）
- 未保存の入力内容の下書き（FR-08）と、設定画面（FR-09）
- リリースのゴール: **署名付きのリリース APK を作り、自分の端末に入れて動作を確認するまで**

### 2.2 対象外
- 自動保存（メモ本体への自動保存。下書きの一時保存 FR-08 は対象）、検索、チェックリスト
- クラウド同期、アカウント・ログイン
- 画像・音声などの添付、手書き
- リマインダー、ウィジェット、ロック
- タブレット・折りたたみ端末向けの専用レイアウト
- iOS・Web 版
- Google Play での配布・公開
- 他アプリへの共有
- 英語など日本語以外の表示

## 3. ユーザー
- 想定ユーザー: 開発者自身（学習用）。ほかの書類で「ユーザー」と書くときは、アプリを使う人としての開発者を指す
- 利用環境: Android 10（API 29）以降のスマートフォン

## 4. 機能要件

詳細は [機能一覧](機能一覧.md) を参照。

| ID | 要件 | 優先度 | 備考 |
|---|---|---|---|
| FR-01 | メモを新規作成できる | 必須 | メモは本文のみ（タイトル欄は持たない） |
| FR-02 | メモを一覧で表示できる | 必須 | 本文の 1 行目と更新日時を表示する。並び順は更新日時の新しい順で固定 |
| FR-03 | 一覧からメモを開いて編集できる | 必須 | |
| FR-04 | 保存ボタンでメモを保存できる | 必須 | 自動保存はしない。保存後は一覧に戻る。未保存のまま戻ろうとしたら「変更を破棄しますか？」と確認する |
| FR-05 | メモを削除できる | 必須 | 確認ダイアログで確認してから削除する。ゴミ箱・元に戻すは持たない |
| FR-06 | アプリを終了・再起動してもメモが残る | 必須 | 保存方式は Room（SQLite） |
| FR-07 | （欠番）メモが 0 件のときの案内表示 | 対象外 | 機能一覧で不要と決定（機能一覧 決定事項 2） |
| FR-08 | 未保存の入力内容を下書きとして一時保存し、システムに終了されたあと戻ってきたときに復元する | 必須 | 下書きは 1 件のみ。編集中にアプリが裏に回ったら一時保存し、戻ってきたときに書きかけの入った編集画面を戻す。アプリを消した・端末を再起動したあとの起動では一覧を開き、書きかけは残さない（決定事項 11）。自動保存（メモ本体への保存）ではない |
| FR-09 | 設定画面で、テーマ（端末に従う／ライト／ダーク。初期値ライト）と一覧・編集画面の文字サイズ（小／中／大。初期値中）を選べ、選択は次回起動時も維持される。アプリのバージョンを表示する | 必須 | 画面一覧で追加（決定事項 13） |

## 5. 非機能要件

| 分類 | 要件 | 確認方法 |
|---|---|---|
| 対応 OS | Android 10（API 29）以降 | minSdk 29 |
| 性能 | アプリ起動からメモ一覧の表示まで **2 秒以内** | 実機で計測（[総合テスト](../総合テスト/テスト設計.md)） |
| 性能 | メモ **1,000 件** でも一覧の表示・スクロールが引っかからない | テスト用データを入れて実機で確認（[総合テスト](../総合テスト/テスト設計.md)） |
| 信頼性 | 保存したメモは、アプリの終了・端末の再起動後も残る | 実機で確認 |
| 信頼性 | 画面の回転など設定変更で、入力中の内容が消えない | UI テスト／実機 |
| 信頼性 | 保存前にアプリがシステムに終了されても、入力中の内容は下書きから復元できる（FR-08） | 実機（開発者向けオプション「アクティビティを保持しない」や `adb shell am kill` で確認） |
| 使いやすさ | 1 画面 1 目的のシンプルな操作。Material Design 3 に沿う | |
| 使いやすさ | ライト／ダークテーマに対応する。設定画面で切り替える（初期値ライト。「端末の設定に従う」も選べる） | [設定 基本設計](../設定/基本設計.md) |
| 言語 | 日本語のみ。画面の文言は `strings.xml` にまとめ、後から言語を追加できる形にする | |
| セキュリティ | 秘密情報はコードに書かない（環境変数・`.env` から読む）。署名鍵もリポジトリに入れない | `.gitignore` で除外。[リリース 基本設計](../リリース/基本設計.md) |
| セキュリティ | 不要な権限（インターネット等）を要求しない | マニフェストで確認（[セキュリティ テスト設計](../セキュリティ/テスト設計.md)） |
| バックアップ | ~~Android 標準の自動バックアップ（Auto Backup）を有効にする~~ → **バックアップしない**（2026-11-17 開発者の決定。メモを端末の外へ出さない。アプリを消す・機種変更するとメモは移らない） | `allowBackup="false"` と、設定ファイルで全部を外す（[共通 基本設計](../共通/基本設計.md) 6.4） |
| 保守性 | 単体テスト・UI テストを書き、`./gradlew test` と `./gradlew connectedAndroidTest` で実行できる | |
| 保守性 | 書類は `docs/` に Markdown で置く | |

※ 性能の数値（2 秒、1,000 件）は打ち合わせで提示した値をそのまま採用した。

## 6. 制約
- 言語・UI: Kotlin + Jetpack Compose
- 開発環境: Android Studio 標準構成（Gradle Kotlin DSL、version catalog、Gradle Wrapper）
- minSdk 29。targetSdk / compileSdk 37
- applicationId は `com.example.sinmemo`（Google Play で配布しないためこのままとする）
- 開発は `claude/...` ブランチで行い PR で取り込む。`main` へ直接コミットしない
- 開発者は 1 人（＋ Claude Code）。期間は [スケジュール](../記録/スケジュール.md) で決める

## 7. テスト方針
- 単体テスト: 保存処理（Room の DAO・リポジトリ）、下書きの保存・復元、画面の状態管理（ViewModel）
- UI テスト: 作成・編集・削除・破棄確認の画面操作（Compose UI テスト）
- 実機確認: 上記に加え、性能（起動時間、1,000 件）、再起動後のデータ保持、リリース APK のインストール
- 各機能のテスト設計は各フォルダの `テスト設計.md`、通しの確認は [総合テスト](../総合テスト/テスト設計.md)。書類の並びは [書類の案内](../README.md)

## 8. 前提・用語
- メモ: 本文のテキストと、作成日時・更新日時からなるデータ
- 一覧画面／編集画面／設定画面: [画面一覧](画面一覧.md) を参照
