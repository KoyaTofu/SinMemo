## 2. 画面の構成

モックアップ（[モックアップ検証](../記録/モックアップ検証.md)）の S-02 に合わせる。

```
┌──────────────────────────────┐
│ ←                    ✓    ⋮ │ アプリバー。✓ は本文が空なら押せない（薄い色）。⋮ は既存メモだけ
├──────────────────────────────┤
│ 牛乳、卵、パン               │
│ 洗剤█                        │ 本文の入力欄（画面いっぱい。長ければ欄の中でスクロール）
│                              │ 空のときは「メモを入力」と薄く表示
│                              │
├──────────────────────────────┤
│              9,688/10,000文字│ 文字数の行。9,500 文字以上のときだけ表示（決定事項 2）
├──────────────────────────────┤
│        （キーボード）        │ 入力欄・文字数の行・上限のメッセージはキーボードの上に出る（決定事項 4）
└──────────────────────────────┘
```

| 部品 | 内容 |
|---|---|
| アプリバー | 一覧と同じ色。左に ←（読み上げ「戻る」）、右に ✓（読み上げ「保存」）と ⋮（読み上げ「メニュー」） |
| メニュー（⋮） | 「削除」の 1 項目だけ。**新規作成中は ⋮ 自体を出さない**（[画面一覧](../要件/画面一覧.md) 決定事項 11） |
| 本文 | 枠線のない入力欄。余白 上下 16dp・左右 20dp、行の高さは文字の 1.7 倍、文字の大きさは設定の文字サイズ（小・中・大）。空のときは「メモを入力」を薄く出す |
| 文字数 | 入力欄の下の別の行に、右寄せで「9,688/10,000文字」の形で出す。9,500 文字以上で出し、10,000 文字ちょうどで赤（`error` の色）になる。本文の上に重ねない（決定事項 6） |
| 上限のメッセージ | 画面の下（キーボードが出ていればその上）に数秒出る帯（Snackbar）。「10,000文字を超えるため入力できません」（→ 7.4 で「貼り付けられません」から変えた。#59 決定 4） |
| 失敗のメッセージ | 上限のメッセージと同じ帯で「保存できませんでした」「削除できませんでした」（7.4。5.1） |
| D-01 削除確認 | 「このメモを削除しますか？」／「キャンセル」「削除」（削除は赤） |
| D-02 破棄確認 | 「変更を破棄しますか？」／「キャンセル」「破棄」（破棄は赤） |

## 3. 動きのルール

### 3.1 言葉の定義
| 言葉 | 意味 |
|---|---|
| 元の本文 | 既存メモは開いたときの本文、新規は空文字 |
| 変更あり | 今の本文が元の本文と 1 文字でも違う（空白・改行も区別する） |
| 空 | 本文が空白・改行（全角スペースを含む）だけ、または何もない（[モックアップ検証](../記録/モックアップ検証.md) 論点 1） |

### 3.2 操作ごとの動き

| 操作 | 条件 | 動き | 画面一覧の遷移 |
|---|---|---|---|
| ✓ | 本文が空 | 押せない | - |
| ✓ | 新規 | 新しいメモとして保存（作成日時・更新日時 = 今）→ 一覧へ | T-07 |
| ✓ | 既存・変更あり | 本文を上書き保存（更新日時 = 今）→ 一覧へ | T-07 |
| ✓ | 既存・変更なし | **保存せず**（更新日時を変えず）一覧へ（[モックアップ検証](../記録/モックアップ検証.md) 論点 2） | T-07 |
| ← ／戻る操作 | 変更なし | そのまま一覧へ | T-08 |
| ← ／戻る操作 | 変更あり | D-02 を出す | T-09 |
| D-02「破棄」 | | 変更を捨てて一覧へ | T-13 |
| D-02「キャンセル」／ダイアログの外を押す／戻る操作 | | ダイアログを閉じて編集を続ける | T-14 |
| ⋮ →「削除」 | 既存のみ | D-01 を出す | T-10 |
| D-01「削除」 | | メモを削除して一覧へ | T-11 |
| D-01「キャンセル」／外を押す／戻る操作 | | ダイアログを閉じて編集画面に残る | T-12 |

- 新規で何も入力していないときは「変更なし」なので、確認なしで一覧に戻る（モックアップの自動確認と同じ）
- 新規で空白だけを入力したときは「変更あり」なので D-02 が出る（モックアップと同じ）
- **保存中の二度押し**: 保存・削除の処理中は ✓・←・「削除」を受け付けない（同じメモが 2 件できるのを防ぐ）
- 一覧へ戻るとき（上の表で「一覧へ」となるもの全部）は、戻る前にキーボードを閉じる（3.6）
- 新規・変更ありの ✓ で保存して戻ったときだけ、一覧は先頭へ戻り、保存したメモが見える。保存せずに戻る・破棄・削除では一覧の位置はそのまま（[メモ一覧 基本設計](../メモ一覧/基本設計.md)。総合テストの不具合 D-1）
- 下書き（書きかけ）を消す操作はない。下書きは画面と一緒に消える（[下書き 基本設計](../下書き/基本設計.md)）

### 3.3 開いたとき
| 場合 | 動き |
|---|---|
| 新規 | 空の入力欄を出し、**入力欄にカーソルを置いてキーボードを出す**（決定事項 1） |
| 既存 | メモを読み込むまで入力欄を出さない（一瞬なので読み込み中の表示はしない）。読み込んだら本文を表示。キーボードは本文を押したときに出す |
| 既存だがメモが見つからない | 何も出さずに一覧へ戻る（通常は起きない。削除直後の古い画面などへの備え） |
| 書きかけを戻して開いた（システムに終了されたあと） | キーボードは自動で出さない（新規でも）。詳しくは [下書き 基本設計](../下書き/基本設計.md) |

### 3.4 本文の上限（10,000 文字）
- 文字数は Android（Kotlin）の文字列の長さ（UTF-16 の単位）で数える。絵文字など一部の文字は 1 文字で 2 と数えるが、上限の目安として割り切る
- **変更後の文字数が 10,000 を超える入力は、丸ごと取り消す**（一部だけ入れることはしない。決定事項 3）
  - 例: 9,990 文字のところに 30 文字を貼り付けると、1 文字も入らず、本文は 9,990 文字のまま（末尾でも文中でも同じ）
  - 例: 9,990 文字のところに 10 文字を貼り付けると、ちょうど 10,000 文字になるので入る
- 取り消したのが **2 文字以上の入力**（貼り付けなど）のときは、「10,000文字を超えるため入力できません」を数秒表示する（→ 7.4 で文を変えた。5.3）
  - 「入力で何文字増えるはずだったか（変更後 − 変更前）」で判断する。選択範囲を置き換える貼り付けは、差し引きの増え方で判断される
  - 1 文字ずつの入力が上限で止まったときはメッセージを出さない（打つたびに出てうるさいため）。文字数が「10,000/10,000文字」（赤）になっているので分かる
  - 入力欄の仕組みからは「貼り付け」と「かな漢字変換の確定」を区別できない。上限ぎりぎりで 2 文字以上を変換・確定した場合も同じメッセージが出るが、まれなので割り切る
- 今の文字数が 9,500 以上（残り 500 文字以下）になったら「今の文字数/10,000文字」を表示する（決定事項 2）
  - 数字は 3 桁ごとにカンマで区切る（例: `9,688/10,000文字`）

### 3.5 画面回転など
- 画面回転では本文も状態（ダイアログの表示など）も消えない（[要件定義書](../要件/要件定義書.md) 非機能要件「信頼性」）
- アプリがシステムに終了された場合の復元は、[下書き 基本設計](../下書き/基本設計.md) で扱う

### 3.6 キーボードの扱い（総合テストの不具合 D-2・D-3 を 7.3 で直した）

| 場面 | 動き |
|---|---|
| 開いたとき | 新規だけ自動で出す（3.3、決定事項 1） |
| キーボードが出ているとき | 入力欄・文字数の行・上限のメッセージが、どれもキーボードの上に出る。隠れない（決定事項 4） |
| 一覧へ戻るとき（✓ で保存・変更なしの ✓・変更なしの ←・D-02「破棄」・D-01「削除」） | **戻る前にキーボードを閉じる**。閉じる指示を出したらすぐ一覧へ移り、消えきるのは待たない（決定事項 5） |

- D-2: 直す前は、入力欄と文字数の行はキーボードを避けていたが、上限のメッセージは画面の下端に出てキーボードに隠れた（総合テストの R-2 で発見）
- D-3: 直す前は、画面を移るときにキーボードを閉じておらず、一覧に移ってからシステムが閉じるまでキーボードが一覧の上に残った（開発者が総合テスト中に気づいた）
- 実機で、一覧の上にキーボードが一瞬でも残って気になるようなら、「消えきるのを待ってから一覧へ移る」に作り直す（決定事項 5。確認は [総合テスト](../総合テスト/テスト設計.md) と [テスト設計](テスト設計.md) の実機 E-D-03）

## 5. 7.4 で変えるところ（Issue #59）

### 5.1 保存・削除の途中で DB が失敗したとき（#59 決定 1）

端末の記憶装置がいっぱい、記憶装置の一時的なエラーなどで、DB への書き込みが失敗することがある。今はアプリが落ちる（入力した本文も消える）。

| 操作 | DB が失敗したときの動き |
|---|---|
| ✓（新規・変更あり） | **落とさない**。画面の下に「保存できませんでした」を数秒出し、**編集画面に残る**。入力した本文・カーソルはそのまま。✓・←・⋮ はまた押せる（もう一度 ✓ で保存し直せる） |
| D-01「削除」 | 落とさない。D-01 を閉じ、「削除できませんでした」を出して編集画面に残る（開発者の決定（2026-11-17）: 決定 1 の文は保存のもの。削除に「保存できませんでした」は合わないので分けた） |

- メッセージはキーボードが出ていればその上に出る（上限のメッセージと同じ帯。決定事項 4）
- 失敗のあと ← を押したときは今までどおり（変更があれば D-02）
- 失敗しても書きかけは残す（[下書き 基本設計](../下書き/基本設計.md) 4 章）
- 開いたとき（既存メモの読み込み）の失敗: 一覧へ戻る（メモが見つからないときと同じ。メッセージは出さない）。書きかけがあっても新規に切り替えない（元のメモが DB に残っているかもしれず、二重になるのを避ける）（開発者の決定（2026-11-17））

### 5.2 保存しようとしたメモがほかで消えていたとき（#59 その他。開発者の決定（2026-11-17））

**スコープ外（開発者の決定（2026-11-17））**: このアプリでは起きない（編集する画面は 1 つで、ほかの端末との同期もない）。念のため、入力を失わない次の動きだけ残す（作りは変えない）。

編集中に、そのメモが DB からなくなっていることがある（総合テストのスクリプトで DB を入れ替えた、バックアップから戻した等。ふつうの使い方では起きない）。今は「書き換えた行が 0 行」でも保存できたことになり、一覧に戻ると本文が消えている。

| 操作 | メモが消えていたときの動き |
|---|---|
| ✓（変更あり） | **新しいメモとして保存する**（作成日時・更新日時 = 今）。一覧に戻り、先頭へ戻す動き（[メモ一覧 基本設計](../メモ一覧/基本設計.md) 5.1）もふつうの新規と同じ。メッセージは出さない |
| ✓（変更なし） | 今までどおり保存しないで一覧へ（DB を見ないので、消えていたことに気づかない。本文は変えていないので失うものはない） |
| D-01「削除」 | 何もせずに一覧へ（もう消えているので、削除できたのと同じ） |

- 理由: 書いた内容を失わない。書きかけを戻すときに元のメモが消えていたら新規として開く決まり（[下書き 基本設計](../下書き/基本設計.md) 決定事項 3）と揃える

### 5.3 本文の上限まわり

| 場面 | 動き | 出典 |
|---|---|---|
| 上限で入らなかったときの文 | 「10,000文字を超えるため**入力できません**」（貼り付けに限らず、変換の確定や絵文字でも出るため） | #59 決定 4 |
| すでに 10,000 文字を超えている本文（スクリプトや古いバックアップで入ったもの） | **減らす変更はできる**（1 文字ずつ消す、選んで消す、短い文に置き換える）。増やす変更は今までどおり取り消す（2 文字以上ならメッセージ）。文字数は「10,250/10,000文字」のように赤で出る。**10,000 文字以下に減らすまで保存できない**: 超えたまま ✓ を押すと保存せず、「10,000文字を超えるため保存できません」を出して編集画面に残る（変更していなくても同じ）。← は今までどおり（変更があれば D-02、なければ一覧へ） | #59 その他（開発者の決定（2026-11-17）。設計役の案の「超えたまま保存できる」から変えた） |
| 絵文字 | 1 つで 2 以上と数える（3.4）。9,999 文字のところに絵文字 1 つは超えるので取り消し、2 増えるはずだったのでメッセージが出る | #59 その他（異常系の確認） |
| かな漢字変換の途中（未確定の文字） | 未確定の文字も数に入る。変換中に超えた入力も取り消す。取り消したあともキーボードで入力を続けられること（変換が止まったままにならないこと）を実機で確かめる。**取り消すと、変換中の文字はひらがなのまま確定され、それ以上は変換できない**（2026-11-17 実機（Gboard）で判明。上限ぎりぎりで漢字にできないだけで、入力は続けられ落ちないので、仕様として受け入れる。開発者の決定（2026-11-17）） | #59 その他（異常系の確認） |
| 巨大な貼り付け（数万文字） | 今までどおり丸ごと取り消し、メッセージ。本文はそのまま | #59 その他（異常系の確認） |
| 保存中の ✓ の二度押し | 今までどおり 1 件だけ保存する（3.2） | #59 その他（異常系の確認） |

- 上限を超えたかの数え方は、入力の上限と同じ（3.4。絵文字 1 つは 2 以上と数える）
- 上限を超えている本文を「減らせない」のは、「変更後の文字数が上限を超えるなら取り消す」という決まりが、もともと超えている本文の削除まで取り消していたため。決まりを「**変更後が上限を超え、かつ変更前より増える**なら取り消す」に変える
