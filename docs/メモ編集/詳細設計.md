## 2. 状態

### 2.1 `MemoEditUiState`（画面の状態）

| 項目 | 型 | 初期値 | 意味 |
|---|---|---|---|
| `isLoading` | 真偽 | false（既存メモは true で始まる） | 既存メモの読み込み中。入力欄を出さない |
| `isNew` | 真偽 | true | 新規作成中。⋮ を出さない、キーボードを出す。下書きを戻すときに元のメモが消えていた場合も true になる |
| `isRestored` | 真偽 | false | 書きかけを戻して開いた。キーボードを自動で出さない（[下書き 詳細設計](../下書き/詳細設計.md)） |
| `isBusy` | 真偽 | false | 保存・削除の処理中。✓・←・「削除」を受け付けない |
| `dialog` | `EditDialog` または なし | なし | 表示中のダイアログ。`Delete`（D-01）／`Discard`（D-02） |
| `showTooLongMessage` | 真偽 | false | 上限のメッセージを出す。画面が出し終えたら `onTooLongMessageShown()` で false に戻す |
| `isClosed` | 真偽 | false | true になったら画面が一覧へ戻る |
| `savedMemoId` | 数値 または なし | なし | 新規・更新で保存して閉じたときの、保存したメモの id。保存せずに閉じたとき（変更なしの ✓・←・破棄・削除）はなし。一覧を先頭へ戻す合図（7.3 で追加。[メモ一覧 詳細設計](../メモ一覧/詳細設計.md)） |

- 本文は状態に入れない（決定事項 1）
- 「✓ を押せるか」と「表示する文字数」も状態に入れず、画面が本文から求める（2.3。決定事項 3）
- 「一覧へ戻る」は 1 回きりのイベントではなく、状態（`isClosed`）で表す（決定事項 2）

### 2.2 ViewModel が持つもの（状態の外）

| 項目 | 公開 | 意味 |
|---|---|---|
| `text`（`TextFieldState`） | する | 本文。画面の入力欄にそのまま渡す。ViewModel が持つので画面回転でも消えない |
| `inputTransformation`（`MaxLengthTransformation`） | する | 上限の取り消し（5 章）。取り消して知らせるときに `showTooLongMessage` を true にする |
| `memoId` | しない | 編集中のメモの id。画面の行き来の引数（`MemoEditRoute` の `memoId`）を `SavedStateHandle` から読む（キー `memoId`）。0（`NEW_MEMO_ID`）なら新規。下書きを戻すときに元のメモが消えていれば 0 に切り替える |
| `original` | しない | 元の本文。「変更あり」（今の本文と違う）の判定に使う |
| `draft` | しない | 書きかけ（`SavedStateHandle` のキー `draftBody`）。[下書き 詳細設計](../下書き/詳細設計.md) |

### 2.3 画面が本文から求めるもの

| 名前 | 求め方 |
|---|---|
| ✓ を押せるか（`canSave`） | 処理中でなく、読み込み中でなく、本文が空でない（`MemoTextLimit.isBlank`） |
| 表示する文字数（`countToShow`） | `MemoTextLimit.countToShow(本文の長さ)`。9,499 以下ならなし |

- どちらも `derivedStateOf` で求める。本文が変わっても、結果が変わったときだけ描き直す

## 3. ViewModel の操作

| 関数 | きっかけ | 受け付けない条件 | 動き |
|---|---|---|---|
| （作るとき） | 画面を開く | - | 新規: 書きかけがあれば本文に入れる。既存: 読み込みを始める（`isLoading` = true） |
| （読み込み） | 作るときに開始 | - | メモあり: `original` = DB の本文、入力欄 = 書きかけ（なければ DB の本文）、`isLoading` = false。メモなし・書きかけあり: 新規に切り替える。メモなし・書きかけなし: `isClosed` = true |
| `onSave()` | ✓ | 読み込み中、処理中、閉じた後、本文が空 | 既存で変更なし: 保存せず閉じる。それ以外: `isBusy` = true → 新規は `repository.create`、既存は `repository.update` → 保存した id を付けて閉じる |
| `onBack()` | ← ／戻る操作 | 処理中、閉じた後 | 読み込み中または変更なし: 閉じる。変更あり: `dialog` = D-02 |
| `onDeleteRequest()` | ⋮ →「削除」 | 新規、読み込み中、処理中 | `dialog` = D-01 |
| `onDeleteConfirm()` | D-01「削除」 | 処理中 | `dialog` を消し `isBusy` = true → `repository.delete` → 閉じる |
| `onDiscardConfirm()` | D-02「破棄」 | - | `dialog` を消して閉じる（保存しない） |
| `onDialogDismiss()` | 各ダイアログの「キャンセル」／外を押す／戻る操作 | - | `dialog` を消す |
| `onTooLongMessageShown()` | 上限のメッセージを出し終えた | - | `showTooLongMessage` = false |
| `onStop()` | 画面が裏に回った | 読み込み中、処理中、閉じた後 | 書きかけを `SavedStateHandle` に入れる（[下書き 詳細設計](../下書き/詳細設計.md)） |

- 「閉じる」は `isClosed` = true にし、保存したときだけ `savedMemoId` に id を入れる（1 か所の非公開関数 `close`）
- 日時はリポジトリ（`RoomMemoRepository` が `Clock` で記録）に任せる。ViewModel は日時を扱わない
- 下書きを消す処理はない（画面を閉じると画面の状態ごと捨てられる。[下書き 詳細設計](../下書き/詳細設計.md)）

### 4.2 閉じるとき（キーボードを閉じてから一覧へ。[基本設計](基本設計.md) 3.6・決定事項 5）
1. `MemoEditScreen` が `isClosed` の変化を見ていて、true になったら
2. 入力欄のフォーカスを外す（`LocalFocusManager.clearFocus(force = true)`）
3. キーボードを閉じる指示を出す（`LocalSoftwareKeyboardController.hide()`）
4. `onClose(savedMemoId)` を呼ぶ。キーボードが消えきるのは待たない

- どの戻り方（✓・←・破棄・削除・メモが見つからない）も `isClosed` を通るので、処理は 1 か所で済む（決定事項 7）

## 5. 上限の仕組み（`MemoTextLimit.kt`）

| 名前 | 種類 | 中身 |
|---|---|---|
| `MAX_LENGTH` | 定数 | 10,000（[機能一覧](../要件/機能一覧.md) F-03） |
| `SHOW_COUNT_FROM` | 定数 | 9,500。この文字数以上で文字数を出す |
| `countToShow(length)` | 関数 | 9,500 以上ならその数、未満ならなし |
| `format(count)` | 関数 | 3 桁ごとのカンマ区切り（英語の区切り方に固定。例: 9688 → `9,688`） |
| `isBlank(text)` | 関数 | 空白・改行・全角スペースだけ、または何もないなら「空」 |
| `MaxLengthTransformation` | クラス（`InputTransformation`） | 入力を確定する前に手を入れる仕組み。上限と「取り消して知らせるときの処理」を受け取る |

`MaxLengthTransformation` の流れ（入力のたびに、確定する前に呼ばれる）:
1. 変更後の長さが上限以下なら何もしない（そのまま入る）
2. 超えていれば、増えるはずだった文字数（変更後 − 変更前）を覚えてから、変更を丸ごと取り消す（`revertAllChanges`）
3. 増えるはずだった文字数が 2 以上なら、知らせる処理を呼ぶ（ViewModel が `showTooLongMessage` を true にする）

## 7. 画面の行き来とのつなぎ（`SinMemoNavHost`）

- 編集画面は `MemoEditRoute(memoId)`。新規は引数なし（0）
- `onClose` では、編集画面がまだ一番上の画面のときだけ一覧へ戻る（`popBackStack`）。保存したメモの id があれば、戻り先の一覧の `SavedStateHandle` に渡す（受け取り方は [メモ一覧 詳細設計](../メモ一覧/詳細設計.md)）
- 一覧から開く操作の二度押し対策は一覧側（`ifResumed`）。編集画面の閉じる処理は `ifResumed` を使わない（決定事項 8）

### 9.2 `onSave()` の順番（#59 決定 1・その他）

受け付けない条件は今のまま。そのあと、まず**上限を超えているか**を見る（開発者の決定（2026-11-17））。

0. `MemoTextLimit.isOverLimit(body)`（`body.length > MAX_LENGTH`。入力の上限と同じ数え方）なら、保存しない。`failure` = `OverLimit`、`failureId` を 1 増やして終わる（`isBusy`・書きかけ・印・DB には触らない。編集画面に残る）。変更なしでも同じ

次に「既存で変更なしなら保存せず閉じる」（今のまま）。そのあとを次の順にする。

1. `isBusy` = true
2. **書きかけを捨て、終わった印を付ける**（DB に書く前）: `savedStateHandle.remove<String>(KEY_DRAFT_BODY)`、`savedStateHandle[KEY_CLOSED] = true`（[下書き 詳細設計](../下書き/詳細設計.md) 6 章。→ 7.4 の確認で、印を付けるのを 4 の「成功」からここへ移した）
3. `viewModelScope.launch` の中で `try`:
   - 新規: `repository.create(body)` → `SavedMemo`
   - 既存: `repository.update(id, body)`。null（0 行）なら 9.3
4. 成功: `close(savedMemo = 戻り値)`（印は 2 で付けてある）
5. 失敗（`catch (e: CancellationException) { throw e }` のあと `catch (e: Exception)`）:
   - `Log.w(TAG, "保存に失敗: ${e::class.simpleName}")`（本文は出さない）
   - `savedStateHandle.remove<Boolean>(KEY_CLOSED)`（2 で付けた印を外す）
   - `savedStateHandle[KEY_DRAFT_BODY] = body`（捨てた書きかけを今の本文で戻す。この後システムに終了されても書いた内容が戻るように）
   - `isBusy` = false、`failure` = `SaveFailed`、`failureId` を 1 増やす（9.1）
   - 本文（`text`）・`memoId`・`original` は触らない

### 9.3 更新が 0 行のとき（#59 その他。開発者の決定（2026-11-17））

**スコープ外**（開発者の決定（2026-11-17））: このアプリでは起きない（画面は 1 つで、同期もない）。念のため、入力を失わない次の動きだけ残す（作りは変えない）。

- `repository.update(id, body)` が null を返したら、続けて `repository.create(body)` を呼び、その `SavedMemo` で 9.2 の 4 へ進む
- `create` が成功したら `memoId` をその id に、`original` を `body` に変える（このあと閉じるので使わないが、状態を正しく保つ）
- `create` が失敗したら 9.2 の 5（`memoId` は元のまま。もう一度 ✓ を押すと、また `update` → 0 行 → `create` の順になる）
- `update` と `create` は 1 つのトランザクションにしない（ほかの画面や仕組みが同じメモを書くことはないため。設計役の案）

### 9.4 `onDeleteConfirm()` の順番（#59 決定 1・その他）

1. `dialog` を消し、`isBusy` = true
2. 書きかけを捨て、終わった印を付ける（9.2 の 2 と同じ）
3. `try { repository.delete(id) }`。0 行（もう消えていた）でも例外は出ないので、そのまま成功として扱う（[基本設計](基本設計.md) 5.2）
4. 成功: `close()`（`savedMemo` はなし。印は 2 で付けてある）
5. 失敗: 9.2 の 5 と同じ。`failure` = `DeleteFailed`

### 9.5 開いたときの読み込みの失敗（開発者の決定（2026-11-17））

- `load()` の `repository.getMemo(memoId)` を `try` で包む。失敗したら `Log.w` して `isClosed` = true（メモが見つからないときと同じ。書きかけがあっても新規に切り替えない）
- 理由: 失敗が一時的なら、元のメモは DB に残っている。新規に切り替えて保存すると同じ内容のメモが 2 件になる

### 9.6 上限の取り消しの条件（`MaxLengthTransformation`。#59 その他）

| | 今 | 7.4 |
|---|---|---|
| 取り消す条件 | `length > maxLength` | `length > maxLength && length > originalText.length`（上限を超え、**かつ増える**変更だけ） |
| メッセージを出す条件 | 増えるはずだった文字数（`length - originalText.length`）が 2 以上 | 同じ |

- `transformInput()` の最初の行を `if (length <= maxLength || length <= originalText.length) return` にする
- すでに上限を超えている本文（DB や書きかけから `setTextAndPlaceCursorAtEnd` で入ったもの。プログラムからの書き込みは `InputTransformation` を通らない）でも、減らす・同じ長さで置き換える変更は通る
- `canSave`（✓ を押せるか）は変えない（上限を超えていても押せる。押すと 9.2 の 0 で保存せず「10,000文字を超えるため保存できません」を出す。[基本設計](基本設計.md) 5.3、開発者の決定（2026-11-17））
- 文字数の行は今の作りで「10,250/10,000文字」（10,000 以上は `error` の色）と出る。変更なし

### 9.7 画面（`MemoEditScreen.kt`・`MemoEditContent`）

- `MemoEditContent` の引数に `onFailureShown: (failureId: Int) -> Unit` を足す。`MemoEditScreen` は `viewModel::onFailureShown` を渡す
- `LaunchedEffect(uiState.failure, uiState.failureId)` で、なしでなければ `snackbarHostState.showSnackbar(文)` → `onFailureShown(failureId)`。上限のメッセージと同じ `SnackbarHostState` を使う（同時には 1 つずつ出る）
- 通し番号も鍵にする理由: 失敗の種類だけを鍵にすると、帯を出している間に同じ種類の失敗がもう一度起きても出し直さない（7.4 の確認役の指摘）。番号が変わると前の表示を打ち切り、新しく出す
- 上限のメッセージの文字列は `R.string.input_too_long` に変える
- `onClose` の型を `(savedMemo: SavedMemo?) -> Unit` に変える。4.2 の閉じる流れ（キーボードを閉じてから `onClose`）は変えない
- プレビューの呼び出しも引数に合わせて直す
