## 1. 範囲と考え方

- 編集画面（S-02）で保存していない変更があるまま**アプリが裏に回り、その間にシステムがアプリを終了した**場合に、戻ってきたとき**書きかけの本文を編集画面ごと元に戻す**
- アプリを**最初から起動したとき**（最近使ったアプリから消した、端末を再起動した など）は、**一覧を開き、書きかけは残さない**（決定事項 1）
- 復元したことは表示しない（[モックアップ検証](../記録/モックアップ検証.md) 論点 4）
- メモ本体への自動保存ではない（F-11 は対象外）
- 書きかけは 1 件だけ（編集画面は 1 つしか開かないため）

## 2. アプリが終了されたあとの開き方

| 場合 | 例 | Android の動き | アプリの動き |
|---|---|---|---|
| A. 画面ごと戻る | 裏に回っている間にメモリ不足などでシステムが終了 → 最近使ったアプリやホームのアイコンから戻る（確かめるときは `adb shell am kill` や、開発者向けオプション「アクティビティを保持しない」で起こす） | 画面の積み重ね（一覧 → 編集）と、各画面が残した「画面の状態」をシステムが元に戻す | 編集画面が開き、**書きかけの本文が入っている** |
| B. 最初から起動 | 最近使ったアプリから消したあと起動、端末の再起動後に起動 | 「画面の状態」は残っていない。開始画面（一覧）から始まる | **一覧を開く。書きかけは残らない**（決定事項 1） |

- ホームのアイコンから起動しても、アプリの画面（タスク）が残っていれば A になる。B になるのは、ユーザーがアプリを消したときと端末の再起動のとき
- 画面回転では書きかけはそのまま残る（[メモ編集 基本設計](../メモ編集/基本設計.md) 3.5）

## 3. 書きかけを残すとき・戻すとき

### 3.1 残すとき
- 編集画面が裏に回ったとき（ホームへ、ほかのアプリへ、電話が来た など）に、そのときの本文を残す
- 変更があるかどうかに関係なく残す（戻したときに元の本文と同じなら「変更なし」になるだけ）
- 保存・破棄・削除で編集画面を閉じると、書きかけも一緒に消える。消す操作はない

### 3.2 戻すとき（A で戻ってきたとき）

| 開いていたメモ | 動き |
|---|---|
| 既存メモ | メモを読み直して「元の本文」にし、**入力欄には書きかけを入れる**。違っていれば「変更あり」なので、← で D-02 が出る。同じなら「変更なし」で、← で確認なしに一覧へ |
| 新規 | 入力欄に書きかけを入れる。✓ で新しいメモとして保存される |
| 既存だが、メモが見つからない（裏に回っている間に消えた。通常は起きない） | 書きかけを入れた**新規作成**として開く（決定事項 3）。⋮ は出さず、✓ で新しいメモとして保存される |

- キーボードは自動で出さない（戻ってきた直後に急にキーボードが出ないように。新規の書きかけでも同じ）
- 書きかけがないとき（B や、ふつうに開いたとき）は今までどおり（[メモ編集 基本設計](../メモ編集/基本設計.md) 3.3）

### 3.3 大きさ
- 本文は最大 10,000 文字。書きかけとして残せる量に十分収まる（[詳細設計](詳細設計.md) 4 章）

## 4. 保存・削除を始めたら書きかけを捨てる（7.4。#59 その他）

### 4.1 直す問題
✓ や D-01「削除」を押してから DB への書き込みが終わるまでの短い間に、アプリが裏に回り、そのままシステムに終了されると、**前に裏に回ったときに残した古い書きかけ**が残ったままになる。戻ってきたときに、保存したはずのメモが古い書きかけの入った編集画面で開き、新規なら ✓ でもう 1 件できてしまう。

### 4.2 決まり（開発者の決定（2026-11-17））

| 時 | 書きかけ | 画面 |
|---|---|---|
| ✓（保存する場合）・D-01「削除」を押した | **すぐに捨て、代わりに「終わった」印を付ける**（DB に書く前。→ 7.4 の確認で、印を付けるのを「終わったあと」から「DB に書く前」に変えた） | 処理中（✓・←・「削除」を受け付けない） |
| 保存・削除が終わった | なし（印は付いたまま） | 一覧へ戻る |
| 処理中か終わったあとに、一覧へ戻る前に終了され、そこから戻った | なし | 「終わった」印を見て、**すぐ一覧へ戻る**（編集画面を出さない。一覧の位置は動かさない） |
| 保存・削除が失敗した（[メモ編集 基本設計](../メモ編集/基本設計.md) 5.1） | **印を外し、今の本文で残し直す** | 編集画面に残る |

- 変更なしの ✓・←・D-02「破棄」は DB に書かないので今までどおり（すぐ閉じる。閉じれば画面の状態ごと消える）
- 失敗のあとに裏に回ったときは、今までどおり裏に回るたびに書きかけを残す（3.1）
- 理由: 書きかけを残すのは「保存していない内容を失わないため」。保存が始まった時点で内容は DB に向かっているので、古い書きかけは要らない。失敗したら DB に入っていないので、書きかけに戻す

### 4.3 そのほかの異常系の確認（7.4）
- 上限ちょうど（10,000 文字）の書きかけも戻る（[テスト設計](テスト設計.md)）
- 上限を超えた本文（10,050 文字のメモを開いたまま裏に回った）の書きかけも、そのまま戻る（減らす変更はできる。[メモ編集 基本設計](../メモ編集/基本設計.md) 5.3）
