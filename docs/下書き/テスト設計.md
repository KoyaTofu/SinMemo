### 1.4 7.4 で足す自動テスト（#59。`MemoEditDraftTest`）

DB への書き込みを途中で止められる偽のリポジトリ（`FakeMemoRepository` に `gate: CompletableDeferred<Unit>?` を足し、`create`・`update`・`delete` の中で待つ）を使い、「処理中」の状態を作る。

| ID | テスト | 確認すること | 出典 |
|---|---|---|---|
| DR-U-15 | `save_removesDraft_beforeDbWrite` | 書きかけ（`draftBody`）がある状態で ✓ → DB の書き込みが終わる前に `draftBody` がなくなっている | #59 その他 |
| DR-U-16 | `delete_removesDraft_beforeDbWrite` | D-01「削除」でも同じ | #59 その他 |
| DR-U-17 | `onStop_whileBusy_doesNotWriteDraft` | 処理中に `onStop()` を呼んでも `draftBody` は入らない | #59 その他 |
| DR-U-18 | `save_success_marksClosed_andRecreateClosesImmediately` | 保存の途中（DB の書き込みを止めている間）に `onStop()` を呼び、その時点の中身を写し取る（Android が裏に回ったときに保存する中身）。そのあと保存を終わらせ、写しから ViewModel を作り直すと、すぐ `isClosed` = true で、`getMemo` を呼ばない。写しには `closed` = true が入り、`draftBody` はない | #59 その他（設計役の案）。7.4 の確認で「状態を保存したあとに保存が終わる」順番に直した |
| DR-U-19 | `save_failure_putsDraftBack` | 保存が失敗すると `draftBody` に今の本文が戻り、`closed` は入らない | #59 決定 1・その他 |
| DR-U-20 | `recreate_draftOf10000Chars_restoresAll` | ちょうど 10,000 文字の書きかけが 1 文字も欠けずに戻り、✓ で保存できる | #59 その他（10,000 文字の書きかけ） |
| DR-U-21 | `recreate_draftOverLimit_restoresAll` | 10,050 文字の書きかけ（上限を超えた本文を開いていた）もそのまま戻る | #59 その他 |
| DR-U-22 | `delete_inProgressSnapshot_recreateClosesImmediately` | D-01「削除」の途中で写し取った中身から作り直すと、すぐ閉じる | 7.4 の確認役の指摘 |
| DR-U-23 | `save_failure_removesClosedMark_thenRecreateRestoresDraft` | 保存が失敗したあとに `onStop()` → 写しから作り直すと、閉じずに今の本文の入った編集画面になる（`closed` が外れている） | 7.4 の確認役の指摘 |

壊す確認（7.4）

| 入れる不具合 | 落ちるはずのテスト |
|---|---|

## 2. エミュレータ

Android 10（API 29）のエミュレータ（`SinMemo_API29`）。Claude が adb で操作する。

| ID | 確認すること | 手順 | 期待 |
|---|---|---|---|
| DR-E-01 | A（既存） | 既存メモを開いて書き換える → ホーム → `adb shell am kill com.example.sinmemo` → 最近使ったアプリから戻る | 書きかけの入った編集画面 |
| DR-E-02 | A（新規） | 新規で入力 → ホーム → `am kill` → 戻る | 書きかけの入った新規作成画面。キーボードは出ない |
| DR-E-03 | B | 書きかけでホーム → 最近使ったアプリから消す → 起動 | 一覧が開き、書きかけはない |
| DR-E-04 | 「アクティビティを保持しない」 | 開発者向けオプションで有効にする → 新規で入力 → ホーム → アイコンから戻る → ✓（終わったら `always_finish_activities=0` に戻す） | 書きかけの入った新規作成画面。キーボードは出ない。✓ で保存できる |
| DR-E-05 | クラッシュしない | 上の確認の間の logcat | クラッシュなし |

### 2.1 エミュレータで確かめるときの注意（5.2 で判明）
- アプリを `adb shell am start -n ...` で起動すると、タスクの「元の起動方法」がホームのアイコンと違うものになり、あとでアイコン（`monkey -p ... -c android.intent.category.LAUNCHER 1`）から戻ったときに**同じタスクに戻らず、一覧から始まる**。A を確かめるときは、最初からアイコンと同じ方法で起動する

## 3. 実機

開発者の端末（OPPO CPH2099、Android 11）で、開発者が確かめる。手順と結果の記入欄は総合テストにある。

| ID | 確認すること | 総合テストの項目 |

| DR-D-01 | 「アクティビティを保持しない」をオン → 書きかけでホーム → アイコンから戻る → 書きかけの入った編集画面（終わったらオフに戻す） | [総合テスト](../総合テスト/テスト設計.md) S-7 |
| DR-D-02 | 書きかけのまま電話を受ける、またはほかの重いアプリをしばらく使ってから戻る → 書きかけが戻る（システムに終了されていなければ、そのまま残っている） | S-8 |
| DR-D-03 | 書きかけのまま最近使ったアプリから消す → 開く → 一覧が開き、書きかけは残らない | S-9 |
| DR-D-04 | 上限ちょうど（10,000 文字）の書きかけが戻る（7.4。#59 その他） | [総合テスト](../総合テスト/テスト設計.md) 5.6 |

- 「保存を始めてから終わるまでの間に裏に回って終了される」は、保存が一瞬で終わるため手では起こせない。自動テスト（DR-U-15〜19・22・23）だけで確かめる

### 3.1 DR-D-04 上限ちょうどの書きかけが戻る（#59 その他）

開発者の端末で、開発者が手で操作する（この端末は adb のタップを受け付けない）。デバッグ版（「SinMemo (debug)」）で、上限近くのメモを `seed` で入れておく（[総合テスト](../総合テスト/テスト設計.md) 5.2）。

| No | ユーザーの操作 | アプリの動き |
|---|---|---|
| 1 | 端末の「設定」の「開発者向けオプション」で「アクティビティを保持しない」をオンにする | - |
| 2 | 「SinMemo (debug)」で「長いメモ 151」を開き、本文の最後に文字を足して「10,000/10,000文字」にする | 文字数が赤になる |
| 3 | ホームボタンを押してホーム画面に戻る | - |
| 4 | ホーム画面の「SinMemo (debug)」を押す | 編集画面が出る。文字数は「10,000/10,000文字」。キーボードは出ない |
| 5 | 本文の最後までスクロールする | 2 で足した文字が最後まで残っている |
| 6 | 「←」を押す | 「変更を破棄しますか？」が出る |
| 7 | 「破棄」を押す | 一覧に戻る |
| 8 | 「アクティビティを保持しない」をオフに戻す | - |
| 例外 1 | 4 で一覧が出たら、3 の前に最近使ったアプリから消していないかを確かめて、2 からやり直す | - |

※用語：アクティビティを保持しない：裏に回った画面をすぐ終了させる、開発者向けの設定。「システムに終了されて戻る」を手で起こすのに使う。終わったら必ずオフに戻す
