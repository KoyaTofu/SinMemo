### 1.3 エミュレータでの確認（メモ 1,000 件、参考値）
AVD `SinMemo_API29`（GPU 描画）に、確認用のメモ 1,000 件を DB へ直接入れ、debug ビルドで計測した。

| ID | 項目 | 結果 |
|---|---|---|
| L-E-01 | コールドスタート（`am start -W` の TotalTime、3 回） | 1,886 ms／1,861 ms／1,813 ms |
| L-E-02 | 一覧の表示 | 先頭から新しい順に表示。20 回のスワイプで 370 件目付近まで問題なくスクロール |
| L-E-03 | スクロール中のフレーム（`dumpsys gfxinfo`） | 464 フレーム、遅れたフレーム 98.9%、中央値 21 ms、90% 28 ms、99% 53 ms |
| L-E-03 | 比較: 同じエミュレータで「設定」アプリを同様にスクロール | 259 フレーム、遅れたフレーム 67.6%、中央値 18 ms、99% 24 ms |
| L-E-04 | クラッシュ（logcat） | なし |

- エミュレータ自体が 1 フレーム 16.7 ms（60fps）に間に合っていない（システムの「設定」アプリでも 67.6% が遅れる）ため、合否は判断できない
- SinMemo は debug ビルド（最適化なし）のため、さらに遅く出ている。非機能要件（起動 2 秒以内、1,000 件で快適）の判定は、実機でリリースビルドを使って行うことにした（→ 実機の結果は 3 章）
- 計測後、確認用のデータは `pm clear` で消した

### 1.4 途中で起きた問題と対応
| 問題 | 原因 | 対応 |
|---|---|---|
| UI テスト 6 件すべてが `NoSuchMethodException: InputManager.getInstance()` で失敗 | `ui-test-junit4` が連れてくる `espresso-core` 3.5.0 が SDK 36 の Android に対応していない | `testImplementation` に `espresso-core` 3.7.0（androidTest と同じ版）を追加 |
| 長い 1 行目の「…」省略を確かめるテストだけ失敗 | Robolectric の既定（LEGACY）の描画では文字の幅を本物どおりに測らないため、省略が起きない | テストクラスに `@GraphicsMode(GraphicsMode.Mode.NATIVE)` を付けた |
| ViewModel のテストで待ち方に注意が必要 | 整形を `Dispatchers.Default`（別スレッド）で行うため、`runTest` の中の `withTimeout`（仮想時間）だと待たずに切れる | `withTimeout` を使わず、`runTest` 自体のタイムアウト（実時間）に任せた |

### 2.3 壊す確認
1 つずつ壊して `--rerun` で実行し、確認後に戻した（記録はスクラッチパッド）。一覧に関わるもの:

| わざと入れた不具合 | 失敗したテスト |
|---|---|
| 一覧で先頭へ戻す処理（`scrollToItem(0)`）を消す | L-U-25、L-U-26、L-U-28、L-U-29（4 件） |
| 一覧で「保存したメモが先頭に来るのを待つ」を消す（すぐ先頭へ戻す） | L-U-25（「新しい一覧が届く前に動いた」） |
| NavHost で、一覧へ id を渡さない | L-U-28、L-U-29（2 件） |

- 「待つ」を消したときは、L-U-28（本物のアプリ）の新規は通った。編集画面から戻る時点で、たいてい DB からの新しい一覧が届いているため。届く前に戻ったときの動きは L-U-25 でしか確かめられないので、L-U-25 を残す
- 同じ確認の途中で、L-U-30（変えずに ←）が 1 回だけ待ち時間切れ（5 秒）で失敗した。壊した箇所とは関係のない操作で、直した版で 5 回続けて流しても再現しなかった。メモを 25 件作る間の待ちなので、待ち時間を 10 秒に延ばした。その後の 3 回は全件成功
- 編集画面側（ViewModel で id を入れない・入れすぎる、キーボード）の壊す確認は [メモ編集 テスト結果](../メモ編集/テスト結果.md)
