## 4. ViewModel（`MemoListViewModel`）

- 受け取るもの: `MemoRepository`、`Clock`（どちらも Hilt）
- `uiState`（`StateFlow<MemoListUiState>`）: `repository.observeSummaries()` を `map` で変換し、`stateIn` で持つ
  - 一覧が届くたびに、`ZonedDateTime.now(clock)` で今の日時を作り、各行を `MemoListFormatter` で整形する
  - 変換は `Dispatchers.Default` で行う（`flowOn`）。1,000 件でも画面のスレッドを止めないため
  - 画面を離れて 5 秒たったら購読を止める（`SharingStarted.WhileSubscribed(5_000)`。画面回転では止めない）
- 画面の操作（メモを押す、＋、設定）は ViewModel を通さず、`MemoListScreen` の引数のコールバックで NavHost に伝える（データを変えない操作のため）

## 5. 整形の関数（`MemoListFormatter`）

| 関数 | 入力 | 出力 |
|---|---|---|
| `title(head)` | 本文の先頭 200 文字（`MemoSummary.head`） | 行に分け（`lineSequence`。LF・CRLF とも分かれる）、`isNotBlank` な最初の行。なければ空文字 |
| `updatedAt(updatedAtMillis, now)` | 更新日時（エポックミリ秒）と今の日時（`ZonedDateTime`） | 更新日時を `now` のタイムゾーンに直し、`now` と同じ年なら `MM/dd HH:mm`、違えば `yyyy/MM/dd HH:mm` |

- Android に依存しない純粋な関数にして、単体テストを簡単にする
- `now` は ViewModel が `ZonedDateTime.now(clock)` で作って渡す（タイムゾーンは `clock.zone`。本番の `Clock` は `DeviceZoneClock` で、端末の今のタイムゾーンを返す。[共通 詳細設計](../共通/詳細設計.md) の 9 章）

## 7. 保存して戻ったときに先頭へ戻す仕組み（7.3、基本設計 5.1）

### 7.1 値の流れ
1. 編集画面の ViewModel は、保存して閉じたときだけ「保存したメモの id」を状態（`savedMemoId`）に入れる（[メモ編集 詳細設計](../メモ編集/詳細設計.md)）。`MemoEditScreen` は `onClose(savedMemoId)` で NavHost に渡す（保存しないときは null）
2. NavHost は、id があれば戻り先（一覧）の `SavedStateHandle` にキー `savedMemoId` で入れてから `popBackStack` する
3. 一覧の行き先は `SavedStateHandle` の `savedMemoId` を `StateFlow` で見て、`MemoListScreen` の `scrollToTopFor` に渡す
4. `MemoListContent` は、`scrollToTopFor` が null でなければ、**その id が一覧の先頭（`items` の 1 件目）に来るのを待って**から `listState.scrollToItem(0)`（アニメーションなし）し、`onScrolledToTop` を呼ぶ
5. NavHost は `onScrolledToTop` で `savedMemoId` を null に戻す

### 7.2 `MemoListContent` に足した引数（7.3）

| 引数 | 既定 | 用途 |
|---|---|---|
| `listState: LazyListState` | `rememberLazyListState()` | テストで位置を見るため、外から渡せるようにした |
| `scrollToTopFor: Long?` | null | 先頭へ戻す合図（保存したメモの id） |
| `onScrolledToTop: () -> Unit` | 何もしない | 戻し終えたことを知らせる |

### 7.3 理由と注意
- 待つ理由: DB からの新しい一覧が届く前に先頭へ戻すと、一覧は「それまで先頭だった行」の位置を保とうとする（`LazyColumn` の `key` の働き）ので、あとから先頭に入った新しい行が上に隠れてしまう
- 保存したメモは更新日時が最新なので、必ず先頭に来る（[共通 詳細設計](../共通/詳細設計.md) の 4.2 の並び順）。→ 7.4: 端末の時計が戻ると先頭に来ないことがあり、待ち続けた（#59 決定 2）。9.3 で作り直す
- 待つ処理は `LaunchedEffect(scrollToTopFor)` の中で、`snapshotFlow` で先頭の id を見て、一致したら進む。最新の `items`・`onScrolledToTop` は `rememberUpdatedState` で読む
- id は `SavedStateHandle` に入れるので、画面回転や、システムにアプリを終了されたあとでも残る。先頭へ戻し終えたら消すので、次に一覧へ戻ったときに再び動くことはない

## 9. 7.4 で変えるところ（Issue #59）

### 9.1 状態に足すもの

`MemoListItem` に 1 つ足す。

| 項目 | 型 | 内容 |
|---|---|---|
| `updatedAtMillis` | Long | 更新日時（エポックミリ秒）。整形する前の値。保存したメモが新しい一覧に入ったかの判定に使う（9.3） |

### 9.2 時刻の変更で作り直す（#59 決定 11。[基本設計](基本設計.md) 3.2）

- `MemoListViewModel` の受け取るものに `TimeChangeSource`（[共通 詳細設計](../共通/詳細設計.md) 13.4）を足す
- `uiState` の作り方を次に変える
  1. `combine(repository.observeSummaries(), timeChanges.changes.onStart { emit(Unit) }) { summaries, _ -> summaries }`（一覧が届いたときと、時刻の知らせが来たときの両方で次へ進む。`onStart` で最初の 1 回を出し、知らせが来る前でも一覧を出せるようにする）
  2. `map` で今までどおり `ZonedDateTime.now(clock)` を作って整形する（知らせのたびに `now` を作り直すので、新しいタイムゾーン・新しい年で出る）
  3. `flowOn(Dispatchers.Default)` → `catch`（9.4） → `stateIn(WhileSubscribed(5_000))` は今のまま
- 知らせの受け手の登録は `stateIn` の購読に合わせて自動で付け外しされる（一覧を見ている間と、離れて 5 秒まで）
- 知らせが続けて来ても（タイムゾーンと時刻の両方が変わる等）、1,000 件の整形が数回走るだけなので、間引かない（設計役の案）
- 整形を動かす場所（`Dispatchers.Default`）は、コンストラクタの引数 `formatDispatcher` で受け取る。Hilt が使う `@Inject` のコンストラクタは `Dispatchers.Default` を渡し、テストはテストの dispatcher を渡す（別スレッドを使わず、仮想の時間だけで進めるため。7.4 の確認で、負荷の高いときにテストが落ちたため変えた）

### 9.3 保存したメモの行までスクロールする（#59 決定 2。[基本設計](基本設計.md) 5.2）

7 章の「先頭に来るのを待つ」を、「**保存したメモが新しい一覧に入るのを待ち、その行へ動かす**」に変える。

値の流れ（7.1 を変える）

| 順 | 部品 | 今 | 7.4 |
|---|---|---|---|
| 1 | `MemoEditViewModel` | 状態の `savedMemoId: Long?` | 状態の `savedMemo: SavedMemo?`（id と、リポジトリが DB に書いた更新日時。[共通 詳細設計](../共通/詳細設計.md) 13.1、[メモ編集 詳細設計](../メモ編集/詳細設計.md) 9.1） |
| 2 | `MemoEditScreen` | `onClose(savedMemoId: Long?)` | `onClose(savedMemo: SavedMemo?)` |
| 3 | `SinMemoNavHost` | 一覧の `SavedStateHandle` のキー `savedMemoId`（Long） | キー `savedMemo` に `longArrayOf(id, updatedAt)` を入れる（`SavedStateHandle` にそのまま入る型にするため）。一覧の行き先は `getStateFlow<LongArray?>` で見て `SavedMemo` に直して渡す。キーの名前の定数は `KEY_SAVED_MEMO` |
| 4 | `MemoListScreen`・`MemoListContent` | 引数 `scrollToTopFor: Long?`、`onScrolledToTop` | 引数 `scrollTo: SavedMemo?`、`onScrolled`（名前を変える。先頭とは限らないため） |
| 5 | `MemoListContent` の `LaunchedEffect(scrollTo)` | `snapshotFlow { items.firstOrNull()?.id }.first { it == id }` のあと `scrollToItem(0)` | 下の手順 |

`LaunchedEffect(scrollTo)` の手順

1. `scrollTo` が null なら何もしない
2. 次の 2 つのうち、先に終わったほうで進む（`select`）。**id と更新日時の両方が合う行**が出るまで待つ（古い一覧にある同じ id の行（更新前の日時）では進まない）
   - 行を探す: `snapshotFlow { items.indexOfFirst { it.id == scrollTo.id && it.updatedAtMillis == scrollTo.updatedAt } }.first { it >= 0 }`
   - 待ち時間: 画面の `Lifecycle`（`LocalLifecycleOwner`）が **RESUMED の間だけ**、0.1 秒ずつ数えて合計 **2 秒**（`SCROLL_WAIT_MILLIS = 2_000`）。RESUMED でない間は `currentStateFlow.first { it.isAtLeast(RESUMED) }` で止まり、数えない（開発者の決定（2026-11-17）。→ 最初は `withTimeoutOrNull(5_000)` で、裏にいる間も数えていた）
3. 見つかったら `listState.scrollToItem(index)`（アニメーションなし）。ふつうは index が 0 なので今までどおり先頭へ戻る。時計が戻ったときは途中の行へ動く
4. 見つかってもタイムアウトでも、最後に `onScrolled()` を呼ぶ（NavHost が `savedMemo` を消す。タイムアウトでは位置を変えない。2 秒は開発者の決定（2026-11-17））

- 待つ理由（7.3 のとおり）は変わらない。待つ相手を「先頭の id」から「id と更新日時」に変えただけ
- 新規保存（0 件から 1 件を含む）は、古い一覧にその id がないので、新しい一覧が届いた時点で見つかる
- 更新は、古い一覧にも同じ id があるが更新日時が違うので、新しい一覧が届くまで進まない（7.3 の「上に隠れる」問題が出ない）
- 7.2 の `listState`・プレビュー・テストの呼び出しも名前に合わせて直す

### 9.4 一覧の読み込みの失敗（#59 決定 1 に合わせた開発者の決定（2026-11-17））

- `uiState` の流れ（`flowOn` の後）に、次の 2 つを入れる。どちらも何も流さないので、画面は**直前の一覧のまま**。アプリは落ちない
  1. `retryWhen`: 一時的なエラー（`IOException`、`SQLiteException` とその仲間）なら、`Log.w` に種類だけを出し、少し待って読み直す。待ち時間は設定と同じ `retryDelayMillis(attempt)`（`data/RetryDelay.kt`。0.5 秒、1 秒…最大 5 秒）。読み直しは購読している間ずっと続ける（→ 7.4 の確認役の指摘で足した。`catch` だけだと、一度の失敗で画面にいる間ずっと一覧が止まっていた）
  2. `catch`: それ以外の例外（作りの間違いなど）は `Log.w(TAG, "一覧を読めなかった: ${e::class.simpleName}")` だけ（`CancellationException` は除く）。流れは止まるが、一覧を 5 秒以上離れて戻ると購読し直すので、そこで読み直す
- 知らせ（開発者の決定（2026-11-17））: `MemoListViewModel.loadErrorId: StateFlow<Int?>`（通し番号）。`retryWhen` と `catch` で失敗したとき、失敗が続いていなければ（`loadFailing` が false）番号を 1 つ進めて入れ、`loadFailing` を true にする。一覧が読めたら（`flowOn` の後の `onEach`）`loadFailing` を false に戻す。画面は番号を鍵に `LaunchedEffect` で「メモを読み込めませんでした」（`memo_load_failed`）を Snackbar で出し、`onLoadErrorShown(番号)` で消す（番号が今のものと同じときだけ）
- `retryWhen` を `flowOn` の後ろに置くのは、待つ処理（`delay`）を画面のスレッド側（テストではテストの仮想の時間）で動かすため
- メッセージは出さない（一覧の読み込みは DB が壊れていない限りまず失敗しない。壊れたときは Room が作り直す。[共通 詳細設計](../共通/詳細設計.md) 13.3）
