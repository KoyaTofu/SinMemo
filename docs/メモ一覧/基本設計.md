## 2. 画面の構成

モックアップの S-01 に合わせる。

```
┌──────────────────────────────┐
│ SinMemo                    ⋮ │ アプリバー。⋮ で「設定」だけのメニュー
├──────────────────────────────┤
│ 牛乳、卵、パン…              │ 1 行目: 本文の最初の空でない行（1 行に収まらなければ「…」）
│ 11/12 14:30                  │ 2 行目: 更新日時（薄い色）
├──────────────────────────────┤ 区切り線
│ 旅行の持ち物                 │
│ 2025/12/28 21:04             │
├──────────────────────────────┤
│                        ┌───┐ │
│                        │ ＋│ │ 「新規作成」ボタン
│                        └───┘ │
└──────────────────────────────┘
```

| 部品 | 内容 |
|---|---|
| アプリバー | タイトル「SinMemo」、右に ⋮（読み上げ「メニュー」） |
| メニュー | 「設定」の 1 項目 |
| 一覧 | 1 行 = 本文 1 行目＋更新日時。行全体を押せる。行の間に区切り線 |
| 行の余白 | 上下 14dp、左右 20dp（モックアップどおり） |
| 「＋」ボタン | 右下。読み上げ「新規作成」。色はアクセント色 |
| 0 件 | 一覧は空のまま。案内文は出さない（[機能一覧](../要件/機能一覧.md) F-02） |

- 一覧の最後の行が「＋」ボタンに隠れないよう、一覧の下に余白（88dp）を空ける
- 文字の大きさは設定の文字サイズに従う（1 行目と日時。[共通 基本設計](../共通/基本設計.md) の 4 章）
- 並び順は更新日時の新しい順で固定。更新日時が同じなら、あとから作ったメモが上

## 3. 表示のルール

### 3.1 本文 1 行目（タイトル）
- 本文を改行で分け、**空白だけでない最初の行**を表示する。行の中身は加工しない（前後の空白も残す）
- 空白には全角スペース・タブも含む。改行は LF・CRLF のどちらでもよい
- 本文の先頭 200 文字の中に空白だけでない行がなければ、空の行として表示する（まれなので割り切る。[共通 詳細設計](../共通/詳細設計.md) の 4.2）
- 1 行に収まらない分は「…」で省略する

**割り切り（#59 決定 5）: 一覧の行が空に見えるメモは、そのままにする**

| 本文の例 | 一覧の 1 行目 | 理由 |
|---|---|---|
| 先頭の 200 文字がすべて空白・改行で、その後ろに文字がある | 空（日時だけの行に見える） | 一覧は本文の先頭 200 文字だけを読む（1,000 件でも速くするため。[共通 詳細設計](../共通/詳細設計.md) 4.2）。空白にはユーザーのレイアウトの意図もありうるので、詰めたり飛ばしたりしない |
| ゼロ幅の文字（U+200B など、幅のない見えない文字）だけ | 空に見える | 「空白だけ」とは判定しないので保存もできる。見えない文字を特別に扱う規則は作らない |

- どちらの行も押せば開ける（行全体を押せる）。開けば本文の全体が見える
- まれなので割り切る（#59 決定 5、開発者）

### 3.2 更新日時
| 条件 | 形式 | 例 |
|---|---|---|
| 今年 | `MM/dd HH:mm` | `11/12 14:30`、`01/05 09:03` |
| 去年以前（と、来年以降） | `yyyy/MM/dd HH:mm` | `2025/12/28 21:04` |

- 時刻は 24 時間制。月・日・時・分は 0 で埋める（[モックアップ検証](../記録/モックアップ検証.md) の論点 3）
- 「今年」かどうかは、**端末のタイムゾーン**で見た現在の年と更新日時の年を比べて決める
- 端末の時計が狂っていて更新日時が未来の年になった場合は、年も表示する（「今年以外」は年を出す、という単純なルールにする）
- 端末のタイムゾーンが変わったら、それに合わせて表示する（[共通 詳細設計](../共通/詳細設計.md) の 9 章）
- ~~制限: 一覧を表示したままタイムゾーンが変わった場合、表示が新しいタイムゾーンになるのは、次にメモが保存・削除されたときか、アプリを起動し直したとき（タイムゾーンの変更を見張る仕組みは作らない）~~ → 7.4 で直す（下の表。#59 決定 11）

**日時の持ち方（7.4 の調べ）**: 日時は世界共通の時刻（エポックミリ秒）で保存し、表示するときに端末の今のタイムゾーンに直す。夏時間・年の境目・並び順（世界共通の時刻で並べる）も正しい。調べて分かった問題は、一覧を開いたままタイムゾーンを変えると、次の保存か、一覧を 5 秒以上離れるまで古い時差のままになることだけだった。

**一覧を開いたまま端末の時刻の設定が変わったとき（#59 決定 11）**

| 変わったもの | 例 | 一覧の動き |
|---|---|---|
| タイムゾーン | 旅行先で自動設定が働いた、設定でタイムゾーンを選んだ | **すぐに**全部の行の日時を新しいタイムゾーンで出し直す |
| 時刻（手で変えた） | 設定で時刻・日付を合わせ直した | すぐに出し直す（「今年」かどうかが変わることがある） |
| 日付（0 時を過ぎた） | 12/31 から 1/1 になった | すぐに出し直す（去年になったメモに年が付く） |

- 端末からの知らせを受けて作り直す。知らせは一覧を見ている間（と、離れて 5 秒まで）だけ受ける。それより長く離れて戻ったときは、戻ったときに作り直す
- 並び順は変わらない（保存した時刻は変わらないため）

## 5. 編集画面から戻ったときの一覧の位置

### 5.1 保存して戻ったときは先頭へ戻す（7.3 で追加。総合テストの不具合 D-1）
一覧のスクロール位置は、編集画面から戻っても保たれる（Compose の標準の動き）。そのため、下のほうまでスクロールしてから保存すると、保存したメモ（先頭）が見えなかった（[総合テスト テスト結果](../総合テスト/テスト結果.md) の不具合 D-1）。保存して戻ったときだけ先頭へ戻す（決定事項 2）。

| 戻り方 | 一覧の位置 |
|---|---|
| 新規作成で ✓（保存） | **先頭へ戻す** |
| 既存メモを変えて ✓（上書き保存） | **先頭へ戻す** |
| 既存メモを変えずに ✓（保存しない。[メモ編集 基本設計](../メモ編集/基本設計.md)） | 今の位置のまま |
| ←／戻る操作（変更なし）、D-02「破棄」、D-01「削除」 | 今の位置のまま（削除は消したメモの分だけ詰まる） |

- 先頭へ戻すときはアニメーションせず、一度に戻す
- 保存したメモが一覧の先頭に出てから戻す。先に戻すと、あとから先頭に入った新しいメモが上に隠れて見えないため
- 画面を回転しても、システムにアプリを終了されて戻っても、先頭へ戻すのは 1 回だけ（もう一度一覧に戻ったときに再び動くことはない）

### 5.2 保存したメモが先頭に来ないとき（7.4 で追加。#59 決定 2）

保存したメモは更新日時が最新なので、ふつうは一覧の先頭に来る。しかし端末の時計が戻っていた（手で過去に合わせた、時刻の自動設定で巻き戻った）ときは、保存したメモの更新日時がほかのメモより古くなり、**先頭に来ない**。5.1 の作りは「先頭に来るのを待つ」だったので、そのときは待ち続け、位置も戻らなかった。

| 保存したメモの位置 | 一覧の動き |
|---|---|
| 先頭（ふつう） | 5.1 のとおり先頭へ戻す |
| 先頭以外（時計が戻った等） | **先頭を待つのをやめ、そのメモの行までスクロールする**（その行が見える位置。アニメーションなし） |

- 「保存したメモが一覧に入った」と分かるまでは待つ（5.1 の、新しい行が上に隠れる問題を出さないため）。分かったら、その行が先頭かどうかに関係なく、その行へ動かす
- 一覧の終わりのほうの行は、画面の一番上までは来ない（一覧の終わりで止まる）。見える位置に来ればよい
- 0 件の一覧で初めてメモを作ったときも同じ（作ったメモが 1 件だけ出る）
- 保存したメモが **2 秒**たっても一覧に入らない（DB の読み込みに失敗した等）ときは、待つのをやめて今の位置のまま（開発者の決定（2026-11-17）。設計役の案の 5 秒から変えた）
- 2 秒は**画面が表示されている間だけ**数える。✓ の直後にホームへ戻るなどで裏にいる間は数えない（裏にいる間に待ち時間が過ぎて、戻っても動かなかった。開発者の決定（2026-11-17）で直した）

### 5.3 一覧の読み込みに失敗したとき（7.4。開発者の決定（2026-11-17））

| 場面 | 一覧の動き |
|---|---|
| 一覧を読めなかった（DB の一時的なエラー等） | 直前の一覧のまま、少し待って読み直す。画面の下に「**メモを読み込めませんでした**」を数秒出す（Snackbar） |
| 失敗が続いている | 読み直しは続けるが、知らせは**続いている間は 1 回だけ** |
| 読めた | 一覧を出し直す。次に失敗したら、また知らせを出す |
