## 2. `app/build.gradle.kts` の署名の処理

`android { }` より前で、署名の情報を集める。

| 名前 | 内容 |
|---|---|
| `signingKeyNames` | 4 項目の名前の一覧（`.env.example` と同じ） |
| `readDotEnv(file)` | `.env` を読んで「項目名 → 値」の表にする。ファイルがなければ空。読み方は [基本設計](基本設計.md) 2.3 |
| `dotEnv` | リポジトリ直下の `.env`（`rootProject.file(".env")`）を読んだもの |
| `signingValues` | 項目ごとに、環境変数（`System.getenv`）→ `dotEnv` の順で、空でない値を探して集めたもの |
| `buildsRelease` | 実行するタスクの名前（`gradle.startParameter.taskNames`）に `Release` を含むか |
| `releaseKeystore` | 4 項目がそろったときの鍵のファイル。そろわなければ null |

処理の流れ:
1. `.env` を読む（BOM を外す → 行ごとに前後の空白を取る → 空行・`#` で始まる行・`=` のない行を飛ばす → 最初の `=` で分ける → 値の両端が同じ `"` か `'` なら外す）
2. 4 項目を環境変数 → `.env` の順に探す
3. `buildsRelease` のときだけ:
   - `releaseKeystore` が null → 足りない項目名を付けて `logger.warn` で警告
   - 鍵のファイルがない → `GradleException` で止める
   - どちらも、パスワードの値は出さない
4. `signingConfigs` で、`releaseKeystore` があるときだけ `release` を作る（4 項目を入れる）
5. `buildTypes.release` の `signingConfig` は `signingConfigs.findByName("release")`。なければ null で、未署名になる
6. `isMinifyEnabled = false` のまま

### 3.2 リリース版の組み立てのときだけ確かめる（#59 その他。開発者の決定（2026-11-17））

AGP の署名の設定（`signingConfigs`）は、値をビルドの設定の段階で渡す必要がある（遅らせて渡す公開の方法がない）。そのため「`.env` を読むこと」と「確かめて警告・エラーを出すこと」を分ける。

| 段階 | すること |
|---|---|
| ビルドの設定（毎回） | ① 実行するタスクの名前が**すべて** `Debug` を含むなら、`.env` を読まない（リリース版は組み立てられないので要らない）。② それ以外は `readDotEnv` で読む。エラーがあっても止めず、結果（値・誤りの行番号・知らない項目名・エラーの文）を覚えておく。③ 4 項目がそろったときだけ `signingConfigs.release` を作る（今のまま） |
| リリース版の組み立ての最初 | タスク `checkReleaseSigning` が、覚えておいた結果から 2.4 の警告・エラーと、6.3 のエラー、6.4 の警告を出す |

`gradle.taskGraph` は使わない（設定の段階のキャッシュと相性が悪く、Gradle も勧めていないため）。代わりに AGP の変種の API で、リリースの変種の組み立てに `checkReleaseSigning` をつなぐ。

| 名前（`app/build.gradle.kts`） | 中身 |
|---|---|
| `onlyDebugRequested` | `gradle.startParameter.taskNames.let { it.isNotEmpty() && it.all { name -> "Debug" in name } }` |
| `dotEnv` | `onlyDebugRequested` なら空の結果。そうでなければ `readDotEnv(rootProject.file(".env"))` |
| `signingValues` | 今のまま（環境変数 → `dotEnv` の値）。`dotEnv` にエラーがあるときは `.env` の値は使わない（環境変数だけ） |
| `checkReleaseSigning` | `tasks.register("checkReleaseSigning")`。設定の段階で、出す文を `List<String>`（警告）と `String?`（エラー）にまとめて取り込み、`doLast` で `logger.warn` と `throw GradleException`。**パスワードの値は文に入れない**（今のまま） |
| つなぎ方 | `androidComponents { onVariants(selector().withBuildType("release")) { variant -> val pre = "pre${variant.name.replaceFirstChar { it.uppercase() }}Build"; tasks.matching { it.name == pre }.configureEach { dependsOn(checkReleaseSigning) } } }` |

- `preReleaseBuild` はリリース版の変種を組み立てるとき（`assembleRelease`、`installRelease`、`bundleRelease`、`assemble`、`build` の中の各リリースのタスク、Android Studio の「Generate APKs」など）に必ず最初に動くタスク。タスクの名前の付け方に頼らずに済む
- 今の `buildsRelease`（タスクの名前に `Release` を含むか）と、設定の段階での `GradleException`（鍵のファイルがない）は消す。鍵のファイルがないエラーも `checkReleaseSigning` で出す
- `releaseKeystore` は今のまま（4 項目がそろったときの鍵のファイル）。ファイルがなくても署名の設定は作る（`checkReleaseSigning` が先に止めるので、AGP のエラーより分かりやすい文が出る）
- 警告の文の中の書類の場所（8.1 の時点では「17_リリース設計 2.4」）は「docs/リリース/基本設計.md 2.4」に直す（[基本設計](基本設計.md) 2.4 の注）。→ 7.4 で直した
- `onlyDebugRequested` の判定が外れる場合（タスクの名前が空の同期など）は、`.env` を読むだけで、警告・エラーは出ない。読むこと自体は害がない（値は署名の設定にしか使わない）

### 3.3 `readDotEnv` の文字コードの判定（#59 決定 8）

戻り値を `Map<String, String>` から次の `DotEnv` に変える（`app/build.gradle.kts` の中の data class）。

| 項目 | 中身 |
|---|---|
| `values: Map<String, String>` | 読めた項目 |
| `linesWithoutEquals: List<Int>` | `=` のない行の行番号（1 から） |
| `unknownNames: List<String>` | `SINMEMO_` で始まり、`signingKeyNames` にない項目名 |
| `nameWarnings: List<String>` | 項目名の書き方の警告の文（小文字・`SINMEMO_` で始まらない・同じ名前が 2 回。[基本設計](基本設計.md) 6.4）。行番号だけを入れ、値は入れない（7.4 の確認で足した） |
| `error: String?` | 文字コードのエラーの文（[基本設計](基本設計.md) 6.3）。なければ null |

処理の順番
1. ファイルがなければ空の `DotEnv`
2. `file.readBytes()` でバイトのまま読む
3. 先頭が `0xFF 0xFE` か `0xFE 0xFF` → `error` = UTF-16 の文で返す
4. 先頭が `0xEF 0xBB 0xBF`（UTF-8 の BOM）→ その 3 バイトを外す
5. `0x00` のバイトがある → `error` = UTF-16 の文で返す（BOM なしの UTF-16 は、ASCII の文字の半分が 0 になるため）
6. `Charsets.UTF_8.newDecoder()` に `onMalformedInput(CodingErrorAction.REPORT)`・`onUnmappableCharacter(CodingErrorAction.REPORT)` を付けて `decode(ByteBuffer.wrap(bytes))`。`CharacterCodingException` → `error` = UTF-8 として読めない文で返す
7. 行ごとの読み方は今のまま（[基本設計](基本設計.md) 2.3）。ただし行の頭の `export `（後ろの空白を含む）は外す。`=` のない行（空・`#` で始まる行は除く）は行番号を `linesWithoutEquals` に入れる
8. 項目名が小文字を含む／`SINMEMO_` で始まらない／前の行と同じ、のときは `nameWarnings` に文を入れる（同じ名前は後の行の値を使う）

- 文の中の `.env の場所` は `file.absolutePath`。中身は入れない
- `checkReleaseSigning` は、`error` があれば何より先にそれで止める。なければ `linesWithoutEquals`・`nameWarnings`・`unknownNames` の警告 → 2.4 の警告・エラーの順
