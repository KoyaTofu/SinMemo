## 1. 範囲

リリースのゴールは「署名付きのリリース APK を作り、自分の端末に入れて動作を確認するまで」（[要件定義書](../要件/要件定義書.md)）。

| 含む | 含まない |
|---|---|
| リリース版の署名の設定（鍵の場所とパスワードを環境変数・`.env` から読む） | Google Play での配布、AAB（`bundleRelease`）、Play App Signing（配布しないため） |

## 2. 署名の情報の渡し方（決定事項 1）

### 2.1 項目
`.env.example` に項目名だけを書く（値は書かない）。

| 項目名 | 内容 | 例 |
|---|---|---|
| `SINMEMO_KEYSTORE_PATH` | 鍵のファイル（キーストア）の場所。**リポジトリの外**に置く | `C:\Users\<名前>\keys\sinmemo-release.jks` |
| `SINMEMO_KEYSTORE_PASSWORD` | キーストアのパスワード | |
| `SINMEMO_KEY_ALIAS` | キーストアの中の鍵の名前 | `sinmemo` |
| `SINMEMO_KEY_PASSWORD` | 鍵のパスワード。4 章の作り方（PKCS12）では `SINMEMO_KEYSTORE_PASSWORD` と同じ値 | |

- `SINMEMO_KEYSTORE_PATH` に相対の場所を書いた場合は、リポジトリ直下から数える（鍵はリポジトリの外に置くので、ふつうは絶対の場所を書く）
- 名前の頭に `SINMEMO_` を付け、ほかのアプリの環境変数とぶつからないようにする

### 2.2 読む順番
項目ごとに次の順で探す。

1. **環境変数**（PowerShell の `$env:SINMEMO_KEY_ALIAS = "..."` など）
2. **リポジトリ直下の `.env`**（`.gitignore` で除外済み）

- 環境変数があればそちらを使う（その場だけ別の鍵で試すときに `.env` を書き換えなくてよい）
- 値が空の項目は、ないものとして扱う
- `.env` を置いておけば、Android Studio のメニュー（Build → Generate APKs など）からも、`.\gradlew.bat assembleRelease` からも、そのまま署名付きでビルドできる

### 2.3 `.env` の書き方
```
# コメント
SINMEMO_KEYSTORE_PATH=C:\Users\<名前>\keys\sinmemo-release.jks
SINMEMO_KEY_ALIAS=sinmemo
```
- 1 行に `項目名=値`。最初の `=` で分け、前後の空白は取る。値を `"` か `'` で囲んでもよい（囲みは外す）
- 行の頭の `export `（シェルの書き方）は外して読む（→ 7.4 の確認で足した）
- `#` で始まる行と空の行は読まない。行の途中の `#` は値の一部として扱う（パスワードに `#` を使えるように）
- `\` はそのまま（Windows の場所をそのまま書ける）。`$` などの展開もしない
- 文字コードは UTF-8（メモ帳の既定）。先頭の BOM は外して読む。→ 7.4: UTF-8 でなければエラーで止める（6.3。#59 決定 8）

### 2.4 署名の情報がないとき（決定事項 2）

| 状態 | リリース版のビルド |
|---|---|
| 4 項目がすべてある | 本物の鍵で署名する。出力は `app/build/outputs/apk/release/app-release.apk` |
| 1 つもない（`.env` もない） | **未署名でビルドし、警告を出す**（`app-release-unsigned.apk`）。クラウドやテストはこれまでどおり動く |
| 一部だけある | 未署名でビルドし、警告に**足りない項目名**を出す（書き忘れに気づけるように） |
| 4 項目あるが、鍵のファイルが見つからない | **エラーで止める**（場所の書き間違いは、未署名で通すより止めたほうが気づきやすい） |
| パスワード・名前が違う | Android のビルド道具（AGP）のエラーで止まる |

- 警告はリリース版を作るとき（実行するタスクの名前に `Release` を含むとき）だけ出す。デバッグ版のビルドや Android Studio の ▶ では出さない。→ 7.4: タスクの名前では `assemble`・`build` のときに素通りしていた。リリース版を本当に作るときに確かめるように変える（6.2）
- 警告にもエラーにも、**パスワードの値は出さない**（項目名と鍵のファイルの場所だけ）
- デバッグ版の署名は今のまま（Android Studio が作るデバッグ用の鍵）。`.env` は読まない。→ 実際は、デバッグ版のビルドでも `.env` を読んでいた（書類との食い違い。#59 その他）。7.4 で、デバッグ版だけを作るときは読まないように直す（6.2）
- 未署名の APK は端末に入らないので、間違って配ることはない

メッセージ

| 場合 | 文 |
|---|---|
| 未署名の警告 | 警告: 署名の情報がないため、リリース版を未署名でビルドします（〈この書類の場所〉）。足りない項目: 〈項目名をカンマ区切り〉 |
| 鍵のファイルがない | 署名の鍵のファイルが見つかりません: 〈場所〉（SINMEMO_KEYSTORE_PATH を確かめてください） |

- 警告の文の中の書類の場所は、8.1 の時点では「17_リリース設計 2.4」。組み直し後はこの 2.4 を指す（`app/build.gradle.kts` の文を直す）

## 4. 鍵の作り方と守り方（8.2、開発者）

### 4.1 作る
開発者の Windows PC で、Android Studio に付いている `keytool` を使う（PowerShell）。

```powershell
New-Item -ItemType Directory -Force "$env:USERPROFILE\keys"
& "C:\Program Files\Android\Android Studio\jbr\bin\keytool.exe" -genkeypair -v `
  -keystore "$env:USERPROFILE\keys\sinmemo-release.jks" -storetype PKCS12 `
  -keyalg RSA -keysize 2048 -validity 10000 -alias sinmemo -dname "CN=SinMemo"
```
- パスワードは、コマンドの中に書かず、聞かれたときに打つ（PowerShell の履歴に残さないため）
- `-validity 10000` は約 27 年。期限が切れると同じ鍵で上書きできなくなるので長くする
- `-dname "CN=SinMemo"`: 鍵の持ち主の名前は APK に入り、だれでも読める。開発者の名前やメールアドレスは入れない
- PKCS12 では鍵のパスワードはキーストアのパスワードと同じになる（`SINMEMO_KEY_PASSWORD` にも同じ値を書く）

### 4.2 置き場所と控え
| もの | 置き場所 | 控え |
|---|---|---|
| 鍵のファイル `sinmemo-release.jks` | `%USERPROFILE%\keys\`（リポジトリの外） | USB メモリなど、PC とは別の場所に 1 つ |
| パスワード | `.env`（リポジトリ直下。`.gitignore` 済み） | パスワード管理アプリなど、鍵の控えとは別の場所 |

- 鍵をなくすと、入れたアプリを上書きできない（消して入れ直すしかなく、メモも消える）。盗まれると、偽のアップデートを作れる（[セキュリティ 基本設計](../セキュリティ/基本設計.md) の守るもの）
- 鍵の控えとパスワードの控えは同じ場所に置かない
- クラウド（Claude のクラウド作業を含む）に鍵と `.env` を渡さない。クラウドでは未署名でビルドする（2.4）

## 5. インストールの手順（8.2、開発者）

| No | 作業 | コマンド・操作 |
|---|---|---|
| 1 | `.env` を作る | `Copy-Item .env.example .env` のあと、メモ帳で 4 項目を書く |
| 2 | 送らないことの確認 | `git status` に `.env` が出ないこと（CLAUDE.md） |
| 3 | 署名付きでビルドする | `.\gradlew.bat assembleRelease`。警告が出ず `app-release.apk` ができること |
| 4 | 署名を確かめる | `& "$env:LOCALAPPDATA\Android\Sdk\build-tools\37.0.0\apksigner.bat" verify --print-certs app\build\outputs\apk\release\app-release.apk` で `CN=SinMemo` が出ること |
| 5 | デバッグ版を消す（データも消える。決定事項 4） | `adb uninstall com.example.sinmemo`（拒まれたら端末の設定から削除） |
| 6 | リリース版を入れる | `adb install app\build\outputs\apk\release\app-release.apk`（端末に確認が出たら許可） |
| 7 | 確かめる | [テスト設計](テスト設計.md) 3 章の RL-D-01〜06 |

- 鍵が違う版は上書きできない（`INSTALL_FAILED_UPDATE_INCOMPATIBLE`）。そのため 5 でデバッグ版を消す。今後 Android Studio の ▶（デバッグ版）で入れるときも、同じ理由で一度消す必要がある。→ 7.4 からはデバッグ版が別のアプリになるので、5 は要らない（6.6）
- 作った APK を残したいときは、リポジトリの外（例: `%USERPROFILE%\keys` とは別のフォルダ）に写す。`build` フォルダはビルドのたびに作り直される

### 6.2 リリース版を作るときだけ `.env` を確かめる（#59 その他）

今の作りの問題

| 問題 | 起きること |

7.4 の決まり

| 場面 | `.env` を読むか | 警告・エラー |
|---|---|---|
| デバッグ版だけを作る（▶、`installDebug`、`assembleDebug`、`testDebugUnitTest`、`connectedDebugAndroidTest` など、実行するタスクの名前がすべて `Debug` を含む） | **読まない** | 出さない |

- 鍵のファイルが見つからないエラーも、リリース版の組み立てのときだけ出す（今は設定の段階で止まる）

### 6.3 `.env` の文字コード（#59 決定 8）

- **UTF-8 だけを読む**。先頭の BOM（メモ帳が付けることがある印）は今までどおり外す
- UTF-16（BOM あり・なし）や Shift_JIS など、UTF-8 でないときは**理由を書いたエラーで止める**（リリース版を作るときだけ。6.2）
- 理由: Windows の PowerShell 5.1 で `"..." > .env` や `Out-File` を使うと UTF-16 で保存される。UTF-16 のまま読むと項目名が見つからず「足りない項目」の警告になり、原因が分かりにくい

| 判定 | 例 | 文 |
|---|---|---|
| 先頭が `FF FE` か `FE FF`（UTF-16 の BOM） | PowerShell 5.1 の `>`・`Out-File` | `.env の文字コードが UTF-16 です。UTF-8 で保存し直してください（メモ帳の「名前を付けて保存」で文字コードを「UTF-8」にする）: 〈.env の場所〉` |
| BOM はないが、0 のバイトを含む（BOM なしの UTF-16） | ほかのエディタの UTF-16 | 同じ文 |
| UTF-8 として正しくないバイトの並びがある | メモ帳で「ANSI」（Shift_JIS）を選んで日本語を書いた | `.env が UTF-8 として読めません（Shift_JIS などで保存されているようです）。UTF-8 で保存し直してください（メモ帳の「名前を付けて保存」で文字コードを「UTF-8」にする）: 〈.env の場所〉` |

- どの文にも `.env` の中身（パスワードなど）は出さない
- 環境変数だけで 4 項目がそろっていても、`.env` があって UTF-8 でなければ止める（壊れたファイルを放っておかないため。設計役の案）

### 6.4 書き方の誤りの知らせ（#59 その他。開発者の決定（2026-11-17））

今は、`=` のない行や、項目名の書き間違い（`SINMEMO_KEYSTORE_PASS` など）は黙って読み飛ばし、「足りない項目」の警告だけが出る。リリース版を作るときに次の警告も出す（止めはしない）。

| 場合 | 文 |
|---|---|
| `#` で始まらず、空でもなく、`=` のない行がある | `警告: .env の 〈行番号〉 行目に「=」がないため読み飛ばしました` |
| `SINMEMO_` で始まるが 2.1 の 4 つのどれでもない項目がある | `警告: .env に知らない項目があります: 〈項目名〉（書き間違いではありませんか。docs/リリース/基本設計.md 2.1）` |
| 項目名に小文字がある（例: `sinmemo_key_alias`）（7.4 の確認で足した） | `警告: .env の 〈行番号〉 行目の項目名に小文字があります（項目名は大文字で書きます。docs/リリース/基本設計.md 2.1）` |
| 項目名が `SINMEMO_` で始まらない（小文字の場合を除く）（7.4 の確認で足した） | `警告: .env の 〈行番号〉 行目の項目名が SINMEMO_ で始まらないため使いません（docs/リリース/基本設計.md 2.1）` |
| 同じ項目名が 2 回以上ある（7.4 の確認で足した） | `警告: .env の 〈行番号〉 行目は 〈前の行番号〉 行目と同じ項目名です。後の行の値を使います` |

- 行の中身は出さない（パスワードの行を書き損じた場合に値が出ないように）。`SINMEMO_` で始まる知らない項目名は秘密ではないので出す。小文字・`SINMEMO_` で始まらない・同じ名前の警告は、行番号だけを出し、項目名も出さない（何が書かれているか分からない行のため）
- 行の頭の `export ` は外してから判定する
